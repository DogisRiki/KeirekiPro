**2. 点検の中の Claude に道具を1つも渡さず、直し方を `edit`・`append_index_line`・`delete` の3つの JSON に限り、事実の調べを10種類の読むだけのコマンドに限る。呼び出しは3回まで** — 部品「点検の中の Claude を呼ぶ部品」「inspect-prompt.md と plan-schema.json」「memory-inspect.pl apply」

- 他にありえた選択肢: 点検の中の Claude に Edit と読む道具を渡して直接直させる。読む道具と読むだけの `git` `gh` の許可だけを渡す。直し方の種類を増やす(行の挿入、ファイルの新規作成)
- 外れていた場合: 要件3 受入基準1-5(重複を1つのメモリファイルにまとめる)、1-6(目次の行の中身をメモリファイルに移す)、1-9(メモリファイルを1つにまとめる)は、`edit` の `old` に当て先の文を含めてつなぎ足す形でしか書けない。点検の中の Claude がその形で書けないと、直しが「行わなかった」として毎週報告に載り、Issue の「種類を問わず直す」が満たされないまま誰も止めない。直すには JSON の形・確認・prompt を作り直す

**4. 点検の状態(設定・記録・報告・比べる元)を git の共通ディレクトリの `keirekipro-memory-inspection/` に置き、比べる元はファイルと行のハッシュだけにする** — データの形

- Issue の記載: あり。「点検ごとの記録が残る」「直す前のメモリの控えを作らない」「所有者のPCの中だけに置く」。置き場所は書かれていない
