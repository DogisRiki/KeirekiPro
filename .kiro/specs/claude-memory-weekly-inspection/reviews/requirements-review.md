**1. 点検が動いていないことと途中で終わったことを開発者に知らせる仕組みを足した** — 要件7(受入基準1〜4)

**2. 報告は、次に開発者がこのリポジトリの Claude Code の会話を始めたときに、会話の始めに示す** — 要件4 受入基準3

**4. 点検は、開発者が PC ごとに1回「使い始める操作」をしてから動く。曜日と時刻は選べ、選ばなければ月曜10時** — 要件1 受入基準1・2・5

- Issue の記載: あり。「所有者が何も打たなくても、点検が週に1回、自動で行われる」。使い始めの操作の有無と、曜日・時刻は書かれていない

- 外れていた場合: 使い始める操作を知らない開発者の PC では点検が一度も動かない。登録の手順と設定の持ち方を作り直す

**6. メモリに書き込むときの決まりは、リポジトリの中にあり、PR で直すものとした** — 要件6 受入基準3、要件2 受入基準1-10

- Issue の記載: あり。「外から混入した指示(所有者以外に由来する指示がメモリに書き込まれた状態)」。確かめ方は書かれていない

- 他にありえた選択肢: メモリの文面だけで判断する。疑いを開発者に見せて答えを待つ
- 外れていた場合: 会話の記録は Claude Code が一定期間で消すため、古いメモリはほとんど「確かめられなかった」になり、この種類の汚染は実質直らない

**8. 量が多すぎる状態の線を、目次が160行か20KB(読み込みの上限の8割)にした** — 要件2 受入基準1-9、要件3 受入基準1-9

- Issue の記載: あり。「量が多すぎる状態」「索引の肥大」。数は書かれていない
- 決めたこと: 160行か20KB
- 他にありえた選択肢: 上限そのもの(200行か25KB)。ほかの割合。メモリファイルの数で見る
- 外れていた場合: 目次が削られすぎる、または上限に達して読み込みから落ちる案内の行が出る。線の数だけを直せばよく、手戻りは小さい
