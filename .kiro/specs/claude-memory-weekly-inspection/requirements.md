# 要件

## 元の要望
Issue #465: Claude Codeのメモリを週次で点検し、汚染を直して改善し続ける

### きっかけ

> Claude Codeのメモリを定期的汚染されていないかチェックし、改善し続ける仕組みが必要。

### 困っていること

- Claude Code のメモリが誤っていても、気づく手段が無い(AIの提案を了承)
- メモリが増え続けて、質が落ちる(AIの提案を了承)

### やりたいこと

- Claude Code のメモリが汚染されていないかを定期的に点検し、改善し続ける
- 点検では次を見つける(AIの提案を了承)
  - 古くなった事実
  - 誤った一般化、未検証の主張が事実として残っている記述
  - メモリ同士の矛盾
  - 外から混入した指示(所有者以外に由来する指示がメモリに書き込まれた状態)
  - 重複と、リポジトリに既に書いてあることの二重記述
  - 索引(`MEMORY.md`)と個別ファイルの食い違い、索引の肥大
  - いまの仕事に合わなくなった記述
  - 索引の説明と本文の食い違い
  - 量が多すぎる状態
  - 置き場所の誤り(メモリではなく CLAUDE.md やリポジトリの文書に書くべき内容)
  - 会話を通らない、外のプログラムによるメモリのファイルの直接の書き換え
- 点検で見つけた汚染は、種類を問わず Claude が直し、直した中身を所有者に報告する(AIの提案を了承)
- 同じ種類の汚染が繰り返し見つかったら、メモリに書き込むときの決まりを見直す。点検で見落としが分かったら、点検の項目とやり方を見直す(AIの提案を了承)

### どうなれば解決か

- 所有者が何も打たなくても、点検が週に1回、自動で行われる(AIの提案を了承)
- 所有者は、決まった曜日と時刻を待たずに、スキルを使って点検を今すぐ動かせる
- 決まった日に所有者のPCが止まっていて点検が行われなかった週は、その週の点検を飛ばし、次の決まった日に点検する(AIの提案を了承)
- 点検の報告が毎回所有者に届く。汚染が無かった回も届く(AIの提案を了承)
- 報告には、直したメモリごとに、直す前の文と直したあとの文が載る。所有者は、おかしい直しを会話で指して、Claude に戻すよう頼める(AIの提案を了承)
- 点検ごとの記録が残る。いつ点検し、何が見つかり、何を直したかが分かる(AIの提案を了承)

### やらないこと

- CLAUDE.md、steering、ほかのプロジェクトのメモリは点検の対象にしない(AIの提案を了承)
- 確かめられないことだけを理由に、メモリを消したり古い扱いにしたりしない(AIの提案を了承)
- メモリ全体や1ファイル全体を、まとめて書き直さない(AIの提案を了承)
- 直す前のメモリの控えを作らない。要らないと決めたメモリは消す(AIの提案を了承)
- 点検の報告と記録を GitHub に出さない。所有者のPCの中だけに置く(AIの提案を了承)

## はじめに

Claude Code は、会話の中で開発者に指摘されたことや、作業の中で分かったことを、メモリとして開発者の PC に書き残し、次の会話の始めに読み込む。メモリは、このリポジトリのすべての作業フォルダで共有される。メモリが誤っていると、Claude はそのあとのすべての会話で誤った前提のまま動く。ところが、今は、開発者がメモリの誤りに気づく手段が無い。また、メモリは増え続けるだけである。

この spec では、Claude が、開発者の PC にあるこのリポジトリのメモリについて、次の5つをするようにする。

- Claude は、メモリを週に1回自動で点検する
- 開発者が頼めば、Claude は、その場でもメモリを点検する
- Claude は、点検で見つけた汚染を直す
- Claude は、直した中身を報告する
- Claude は、点検ごとの記録を残す

この spec で使う言葉は次のとおりである。

- メモリ: Claude Code が開発者の PC に書き残す、このリポジトリについての覚え書きである。メモリは、目次と、メモリファイルから成る
- 目次: メモリの `MEMORY.md` である。目次には、メモリファイルごとに、ファイルへの案内の行がある。Claude Code は、会話の始めに、目次の先頭の200行か25KBのうち少ないほうまでを読み込む。Issue の本文の「索引」は、この目次を指す
- メモリファイル: 目次のほかの、1つの覚え書きを書いたファイルである
- 点検: Claude がメモリを読んで汚染を見つけ、直す作業の1回分である
- 報告: 点検が終わるたびに Claude が作り、開発者に示す文書である
- 記録: 点検ごとに残る、点検の日時と、見つけた汚染と、直した中身を書いた文書である
- 汚染: メモリファイルの記述と目次のうち、点検で見つけて直す対象のものである。どの記述を汚染とみなすかは、要件「点検で見つける汚染」に書く
- 開発者: このリポジトリで Claude Code を使う人である。Issue の本文の「所有者」を、この spec では、点検が動く PC で Claude Code を使う開発者と読む。メモリは開発者の PC ごとにあり、ほかの開発者の PC とは共有されないためである

## 範囲

- この spec で決めること: この spec では、次の7つを決める。
  - 点検をいつ動かすか
  - 点検で、どの種類の汚染を見つけるか
  - Claude が汚染をどう直すか
  - 報告に何を載せ、開発者にどう示すか
  - 点検ごとの記録をどう残すか
  - 点検が動かなかったときと、点検が失敗したときに、どう扱うか
  - メモリに書き込むときの決まりと、点検のやり方を、どう見直すか
- この spec で決めないこと: この spec では、次の2つを決めない。
  - 点検を動かす仕組みに何を選ぶか
  - ほかの開発者のメモリを集めて点検すること
- この spec が前提にしていること: この spec は、次の3つを前提にする。
  - 開発者の PC で Claude Code が使える
  - 点検の中で Claude Code が Claude にメモリの中身を送ることは、ふだんの会話で Claude Code がメモリを読み込むことと同じ扱いであり、元の要望の「点検の報告と記録を GitHub に出さない」の対象に入らない
  - 点検は、開発者ごとに、その開発者の PC で動き、Windows・macOS・Linux のどれの PC でも同じように動く

## 要件

### 要件1 点検を週に1回自動で動かし、その場でも動かせるようにする

メモリの誤りは、開発者が気づかないうちに増える。開発者が点検を始めるコマンドを打たなければ点検が動かない作りにすると、点検は行われなくなる。開発者は、点検のことを思い出さなければ、そのコマンドを打たないためである。そこで、点検は、開発者が何も打たなくても週に1回動く。一方で、開発者が、次の決まった曜日と時刻を待たずに、すぐに点検したいときもある。そこで、開発者は、スキルを使って、点検をその場で動かすこともできる。

1. 開発者が点検を使い始める操作を PC ごとに1回すると、そのあとは、開発者が何も打たなくても、点検は毎週決まった曜日と時刻に1回動く。
2. 開発者は、点検を使い始めるときに、点検が動く曜日と時刻を選べる。開発者が選ばなかったときは、点検は毎週月曜日の10時に動く。
3. 開発者が点検を使い始める操作を2回以上しても、点検は週に1回だけ動く。
4. 決まった曜日と時刻に PC が止まっていたかスリープしていて、点検が動かなかった週は、その週の分の点検は行われない。PC が動き出したあとにも、その週の分の点検は遅れて行われない。点検は、次の決まった曜日と時刻に動く。
5. 開発者が点検をやめる操作を1回すると、そのあとは点検は動かない。
6. 点検が動いている間も、開発者は、同じ PC で Claude Code の会話を続けられる。
7. Claude は、点検の中で、このリポジトリのメモリだけを点検する。Claude は、ほかのプロジェクトのメモリ、CLAUDE.md、steering を点検しない。Claude は、メモリの記述が正しいかを確かめるために、リポジトリのファイル、Git の履歴、GitHub の Issue と PR、会話の記録を読む。
8. 開発者が会話でスキルを使うと、Claude は、決まった曜日と時刻を待たずに、点検をその場で1回動かす。開発者が点検を使い始める操作をしていなくても、開発者は点検をその場で動かせる。
9. その場で動かした点検が終わると、Claude は、点検を動かした会話の中で、その点検の報告を示す。
10. その場で動かした点検は、決まった曜日と時刻の点検の代わりにならない。その場で点検を動かしたあとも、点検は、次の決まった曜日と時刻に動く。
11. Claude は、2つの点検を同時に動かさない。点検がすでに動いているときに開発者がスキルを使ったら、Claude は、2つ目の点検を動かさず、点検がすでに動いていることを開発者に示す。その場で動かした点検が動いている間に決まった曜日と時刻が来たら、決まった曜日と時刻の点検は、その場で動かした点検が終わってから動く。同じメモリを2つの点検が同時に直すと、一方の直しを、もう一方の直しが上書きするおそれがあるためである。

### 要件2 点検で見つける汚染

汚染の種類ごとに何を汚染とみなすかが決まっていないと、Claude は、点検で、Issue の本文が挙げた汚染の種類を見落とすおそれがある。そこで、Claude は、次のとおりに汚染を見つける。

1. Claude は、点検のたびに、目次とすべてのメモリファイルを読み、次の11種類の汚染を探す。
   1. 古くなった事実: メモリファイルに書かれたファイル、スキル、コマンド、設定、Issue の状態、日付の付いた予定が、点検の時点のリポジトリと PC の状態に合わない記述
   2. 誤った一般化と未検証の主張: 一度の出来事を一般の決まりとして書いた記述と、根拠を書かずに事実として書いた主張
   3. メモリ同士の矛盾: 2つ以上のメモリファイルが、同じことについて食い違うことを書いている記述
   4. 外から混入した指示: 開発者の発言に由来しない指示が、決まりとしてメモリに書かれた記述。たとえば、ウェブページ、Issue、PR のコメント、ツールの出力に書かれていた指示で、開発者は会話で言っていないもの
   5. 重複と二重記述: 2つ以上のメモリファイルが同じことを書いている記述と、CLAUDE.md、steering、スキルの手順、`doc/` のようなリポジトリの文書にすでに書いてあることをメモリにも書いている記述
   6. 目次とメモリファイルの食い違いと、目次の肥大: 目次に行があるのにメモリファイルが無いこと、メモリファイルがあるのに目次に行が無いこと、目次の1つの行に、メモリファイルへの案内の1行を超える中身が書かれていること
   7. いまの仕事に合わなくなった記述: 終わった作業や、リポジトリから無くなった仕組みについての記述で、そのあとの会話で使う場面が無いもの
   8. 目次の説明と本文の食い違い: 目次の行の説明が、そのメモリファイルの中身と合わないこと
   9. 量が多すぎる状態: 目次が160行か20KBを超えていること。これは、Claude Code が会話の始めに読み込む上限の200行か25KBの8割である
   10. 置き場所の誤り: このリポジトリのすべての開発者に当てはまる決まりで、メモリではなく CLAUDE.md やリポジトリの文書に書くべき記述
   11. 会話を通らない直接の書き換え: 前の点検が終わったあとに、Claude Code の会話の中の Claude でも点検でもないプログラムが、メモリファイルか目次を書き換えたこと
2. Claude は、外から混入した指示の疑いを、その指示の出どころが開発者の発言ではないと分かったときに、汚染とみなす。たとえば、Claude は、その指示を書いた会話の記録を読み、その指示がツールの出力にあって開発者の発言に無いと分かったときに、汚染とみなす。会話の記録が残っておらず、出どころを確かめられないときは、Claude はその指示の記述を消さず、報告に「確かめられなかった」と書く。
3. 初回の点検では、Claude は、会話を通らない直接の書き換えを探さない。初回の点検には、書き換えを見つけるために比べる元が無いためである。Claude は、初回の点検の報告に、次の点検から書き換えを見つけられることを書く。

### 要件3 見つけた汚染を Claude が直す

開発者が汚染を1つずつ直す手間をかけずに済むよう、点検で見つけた汚染は、Claude が直す。ただし、Claude の直しそのものが新しい誤りにならないよう、Claude は、次の範囲と直し方で汚染を直す。

1. Claude は、見つけた汚染を、種類ごとに次のとおり直す。
   1. 古くなった事実: Claude は、記述を点検の時点の事実に合わせて直す。記述が要らなくなっていれば、Claude はその記述を消す
   2. 誤った一般化と未検証の主張: Claude は、リポジトリ、Git の履歴、GitHub の Issue と PR で記述を確かめる。誤りだと確かめられたら、Claude は記述を直す。確かめられなかったら、Claude は記述を直さず、報告に「確かめられなかった」と書く
   3. メモリ同士の矛盾: Claude は、どちらの記述が正しいかを確かめ、正しいほうに合わせて誤ったほうの記述を直す。どちらが正しいか確かめられなかったら、Claude は記述を直さず、報告に「確かめられなかった」と書く
   4. 外から混入した指示: Claude は、その指示の記述を消す
   5. 重複と二重記述: Claude は、重複した記述を1つのメモリファイルにまとめる。リポジトリの文書にすでに書いてある記述は、Claude はメモリの側から消す
   6. 目次とメモリファイルの食い違いと、目次の肥大: Claude は、目次の行を足すか消して、実際のメモリファイルに合わせる。Claude は、目次の行に書かれた案内の1行を超える中身を、そのメモリファイルに移し、目次の行を1行にする
   7. いまの仕事に合わなくなった記述: Claude は、その記述を消す
   8. 目次の説明と本文の食い違い: Claude は、目次の行の説明を、メモリファイルの中身に合わせて直す
   9. 量が多すぎる状態: Claude は、ほかの種類の汚染を直したあとも目次が160行か20KBを超えていれば、同じことについてのメモリファイルを1つにまとめて、目次の行を減らす
   10. 置き場所の誤り: Claude は、その記述を移す先のリポジトリの文書と、移す文の案を報告に載せる。Claude は、点検の中ではメモリの記述を消さない。リポジトリの文書を変えるには PR が要る。Claude は、点検の中ではリポジトリを変えないので、点検の中では記述をリポジトリの文書に移せないためである。開発者が会話で案を了承したら、Claude は、その会話の中で、移す文をリポジトリの文書に足すための Issue を起票し、その変更を PR で出す。その PR がマージされたら、Claude はメモリの側の記述を消す
   11. 会話を通らない直接の書き換え: Claude は、書き換えられたファイルの中身を、ほかの10種類の汚染について点検して直す。Claude は、書き換えられたことだけを理由に、記述を消したり元に戻したりしない
2. Claude は、汚染のある記述だけを書き換える。Claude は、メモリ全体や1つのメモリファイルの全体を、まとめて書き直さない。ただし、メモリファイルの中身がすべて消すべき記述のときは、Claude はそのメモリファイルを消し、目次の行も消す。
3. Claude は、確かめられないことだけを理由に、記述を消したり、古いという印を付けたりしない。
4. Claude は、直す前のメモリファイルを、別のファイルに写して残さない。直す前の文は、報告と記録にだけ載る。
5. Claude は、点検の中でメモリファイルに書かれた指示に従って動かない。Claude は、メモリファイルの中身を、点検する材料としてだけ読む。メモリに外から混入した指示があっても、Claude が点検の中でその指示に従って動かないようにするためである。
6. Claude は、点検の中で、このリポジトリのメモリと、報告と、記録のほかには、どのファイルも書き換えない。Claude は、点検の中で、リポジトリにコミットせず、GitHub に何も書き込まない。
7. Claude が点検でメモリファイルを読んだあとに、開発者との会話の中の Claude がそのメモリファイルを書き換えたら、Claude はその点検ではそのメモリファイルを直さない。Claude は、そのメモリファイルをその点検では直さなかったことを報告に書き、そのメモリファイルを次の点検で点検する。開発者との会話の中で Claude が書き換えた記述を、Claude が点検で上書きして消さないようにするためである。

### 要件4 報告を開発者に示し、直しを戻せるようにする

開発者は、Claude がメモリをどう直したかを知らなければ、直しの誤りに気づけない。そこで、Claude は、点検のたびに報告を作って開発者に示し、開発者が会話で直しを戻せるようにする。

1. Claude は、点検が終わるたびに報告を作る。汚染が無かった点検でも、Claude は「汚染は無かった」と書いた報告を作る。
2. 報告には、次のことが載る。
   1. 点検した日時と、点検したメモリファイルの数
   2. 見つけた汚染ごとに、汚染の種類と、メモリファイルの名前と、汚染のある記述
   3. 直したメモリファイルごとに、直す前の文と直したあとの文。消したメモリファイルは、消す前の全文
   4. 直さなかった汚染ごとに、直さなかった理由
3. 点検が終わったあとに、開発者がその PC でこのリポジトリの Claude Code の会話を始めると、Claude は、会話の始めに、まだ開発者に示していない報告をすべて示す。
4. 開発者が会話で報告の直しを指して戻すよう頼むと、Claude は、そのメモリファイルの記述を直す前の文に戻す。消したメモリファイルを戻すよう頼まれたら、Claude は、報告に載った消す前の全文でメモリファイルを作り直し、目次の行も戻す。
5. 開発者が戻した直しについて、Claude は、そのあとの点検で、その記述の文面が変わらない限り、同じ直しをしない。Claude が次の点検で同じ直しをまた行うと、開発者は毎週同じ直しを戻すことになるためである。

### 要件5 点検ごとの記録を開発者の PC に残す

Claude は、点検ごとの記録を残し、Claude がいつ点検し、何を見つけ、何を直したかを、開発者があとから確かめられるようにする。報告と記録にはメモリの中身が載るので、外には出さない。

1. Claude は、点検ごとに記録を残す。記録には、点検した日時、見つけた汚染、直したメモリファイルごとの直す前の文と直したあとの文、直さなかった汚染とその理由が載る。
2. 開発者が直しを戻したときは、Claude は、戻した直しを、その直しを行った点検の記録に書き足す。
3. Claude は、報告と記録を、開発者の PC の中の、リポジトリにコミットされない場所に置く。
4. Claude は、開発者との会話の中でも、報告と記録の中身を Issue や PR に書き写さない。ただし、Claude は、開発者が会話で了承した次の2つの案を、その案のために起票する Issue と、その PR に書く。1つ目は、メモリの記述をリポジトリの文書に移す文の案である。2つ目は、メモリに書き込むときの決まりや点検のやり方の見直しの案である。この2つの案は、リポジトリの文書に足す文である。このリポジトリでは、Issue を起票して PR を出さなければリポジトリを変えられないためである。
5. 開発者が会話で過去の点検について尋ねると、Claude は、記録を読んで、いつ点検し、何が見つかり、何を直したかを示す。

### 要件6 メモリに書き込むときの決まりと点検のやり方を見直す

同じ種類の汚染が繰り返しメモリに入るなら、汚染を直すだけでなく、汚染が入らないように、メモリに書き込むときの決まりを変えるべきである。点検が見落とした汚染があれば、点検のやり方を変えるべきである。

1. 同じ種類の汚染が、直近の4回の点検のうち2回以上で見つかったら、Claude は、メモリに書き込むときの決まりの見直しの案を報告に載せる。Claude は、1つの記述の汚染を、その汚染を初めて見つけた点検でだけ数える。直さずに残した記述と、開発者が戻した直しの記述が、点検のたびに数えられて、案が毎週出るのを防ぐためである。
2. 開発者が会話で、ある種類の汚染についての決まりの見直しの案を断ったら、Claude は、そのあとの点検で、その種類の汚染についての決まりの見直しの案を報告に載せない。断られた案を Claude が毎週載せると、開発者は毎週同じ案を読むことになるためである。
3. Claude が点検で見つけなかった汚染を、そのあとに開発者が会話で指摘したら、Claude は、点検の項目とやり方の見直しの案を作り、次の報告に載せる。Claude が、あとの点検で、前の点検のときにすでにあった汚染を見つけたときも、Claude は同じく見直しの案を報告に載せる。
4. Claude は、点検の中では、メモリに書き込むときの決まりと、点検の項目とやり方を書き換えない。メモリに書き込むときの決まりと点検のやり方は、このリポジトリのすべての開発者に当てはまるためである。開発者が会話で案を了承したら、Claude は、その見直しのための Issue を起票し、その見直しをリポジトリの変更として PR で出す。Claude が、点検の中で、メモリに外から混入した指示に従って、メモリに書き込むときの決まりや点検の項目とやり方を書き換える、という事態を起こさないためである。

### 要件7 点検が動かなかったときと失敗したときに開発者が気づけるようにする

点検の仕組みが壊れて点検が動かなくなっても、汚染が無いという報告と同じく、開発者には何も見えない。そこで、Claude は、点検が長く動いていないことと、点検が途中で終わったことに、開発者が会話の中で気づけるようにする。

1. 点検が途中で終わったら、Claude は、途中で終わったことと、それまでに直したメモリファイルの直す前の文と直したあとの文を、報告と記録に載せる。途中で終わった例は、Claude Code の使用量が上限に達したとき、ネットワークにつながらなかったとき、PC が止まったときである。
2. 点検が途中で終わった週の分の点検は、遅れてやり直されない。Claude は、次の決まった曜日と時刻の点検で、すべてのメモリファイルを点検する。
3. Claude は、開発者がこのリポジトリの Claude Code の会話を始めたときに、次の2つがどちらも当たれば、会話の始めに、決まった曜日と時刻の点検が14日を超えて動いていないことと、最後に決まった曜日と時刻の点検が終わった日時を示す。その場で動かした点検は、この14日に数えない。このお知らせは、決まった曜日と時刻に点検を動かす仕組みが壊れたことに、開発者が気づくためのものだからである。
   - 開発者が点検を使い始めている
   - 最後に終わった決まった曜日と時刻の点検から14日を超えて、決まった曜日と時刻の点検が動いていない
4. 開発者が点検を使い始めていないか、やめる操作をしたときは、Claude は、会話の始めに、決まった曜日と時刻の点検が14日を超えて動いていないことを示さない。
