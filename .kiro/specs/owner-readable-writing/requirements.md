# 要件

## 元の要望(Issue #590 の本文と、着手のときに所有者が決めたこと)

Issue #590: AIの報告・問い・spec の本文が、所有者が読んでも意味の分からない文になる

### きっかけ

#577 の要件の審査を終えたあと、AIが所有者に出した問いが、何度も続けて意味の通らない文になった。所有者が起票を指示した。

### 困っていること

- AIが所有者に出す報告と問いには、主語や目的語が抜けた文や、AIが作業の中だけで使っている言葉が入る。所有者が読んでも意味が分からない。
- 所有者が毎回「わかりやすく書いて」と言わないと、AIはわかりやすく書かない。
- spec の本文も読みにくい。

### やりたいこと

以下は、`/kiro-spec-init #590` の会話で、AIが出した問いに所有者が答えて決めたことである。

- 対象の文は、チャットの報告と問い、spec の本文、Issue の本文、PR の本文の4つにする。コミットメッセージとコードの中のコメントは対象にしない(AIの提案を了承)
- AIは、文を送る前に、その文を自分で読み直す。決まりから外れた文があれば、AIが直してから送る。別のエージェントには読ませない。別のエージェントに読ませると、費用がかかり、返事が遅くなるためである(要件の審査のあとに所有者が決めた)
- わかりやすく書くための決まりは、リポジトリに置く。Claude Code のメモリにある書き方の決まりは、この spec でリポジトリに移し、メモリから消す(AIの提案を了承)
- 所有者がこれまでに差し戻した種類の文を、わかりにくい文とする。主語や目的語が抜けた文、作業の中だけで使っている呼び名を使った文、造語を使った文、種類の違うものを1つの言葉でまとめた文、名詞を並べただけの文、括弧に補足を詰め込んだ文、矢印でつないだ文である(AIの提案を了承)
- 上の種類のほかに、どんな文をわかりにくい文とするかを、AIと所有者の壁打ちで詰める。AIが「この文はどうか」と例を出し、所有者が答えるやりとりを、出す例が尽きるまで繰り返す。やりとりは最大20回とし、20回に達しても尽きていなければ、最大の回数を5回ずつ増やして続ける。壁打ちで決まった種類は、下の「壁打ちで決めた、わかりにくい文の種類」に書き足す
- 所有者が新しい種類のわかりにくい文を指摘したら、AIは、指摘された文と書き直した文を、例として決まりに足す変更を作り、PRで出す(AIの提案を了承)

### どうなれば解決か

- 所有者がこれまでに差し戻した文を集めて、例の一覧を作る。一覧のどの文も、AIが送る前の読み直しで直せることを確かめる。書き直した文は、直す必要が無いと判断されることも確かめる(AIの提案を了承)
- 例の一覧には、Claude Code のメモリに残した差し戻しに加えて、Claude Code の会話の記録(2026-08-10〜2026-10-19)で所有者が差し戻した文も入れる(所有者に「ほかのセッションで注意したものも全て控えているか」と問われ、AIがメモリしか見ていなかったため足した)

### やらないこと

- 今ある spec の本文は書き直さない。これからAIが書く文だけを対象にする(AIの提案を了承)

## はじめに

所有者は、Claude が書いた報告・問い・spec・Issue・PR の文を読んで、作業を進めるかどうかを判断する。今は、Claude が送る文に、主語や目的語の抜けや作業の中だけで使う呼び名が入り、所有者が読んでも意味が分からないことが続いている。

今の書き方の決まりは、spec の本文の決まりが `.kiro/settings/rules/spec-writing.md` にあるほかは、Claude Code のメモリと、CLAUDE.md と、スキルの手順に分かれて書かれている。メモリは所有者の PC にだけあり、ほかの人の PC の Claude は読めない。また、Claude が送る前に文を決まりと照らして読み直す手順は、どこにも書かれていない。

この spec では、Claude は、所有者に送る文に共通の書き方の決まりをリポジトリに置き、送る前に、その決まりと照らして文を自分で読み直す。Claude は、所有者がこれまでに差し戻した文を使って、読み直しで差し戻された文を見つけられることと、直した文を外れたと判断しないことを確かめる。

この spec でいう所有者に送る文は、次の4つを指す。

- チャットの報告と問い: Claude が1回の返事の終わりに書く本文と、返事の最後に出る、まとめの文とボタン付きの質問
- spec の本文: requirements.md、design.md、tasks.md
- Issue の本文: Claude が起票するときの本文と、Claude が本文に書き足すときの文
- PR の本文: Claude が PR を作るときの本文と、Claude が本文を書き換えるときの文

## 範囲

- この spec で決めること:
  - 所有者に送る文の書き方の決まりを、どこに、何を書いて置くか
  - Claude が所有者に送る文を、送る前に自分で読み直すこと
  - 所有者がこれまでに差し戻した文を集めた例の一覧と、その一覧を使った確かめ方
  - 所有者がわかりにくい文を指摘したときに、Claude が決まりに例を足すこと
  - メモリにある書き方の決まりを、リポジトリに移してメモリから消すこと
- この spec で決めないこと:
  - コミットメッセージとコードの中のコメントの書き方
  - Claude が作業の途中に書く一言。Claude は、この一言も決まりに沿って書くが、要件2の読み直しはしない。一言は作業の進み具合を知らせるだけで、所有者が作業を進めるかどうかの判断に使う文ではないためである
  - Claude が Issue と PR に書くコメントの書き方
  - README.md と `doc/` の文書の書き方
  - CLAUDE.md、スキルの手順、エージェントの定義のように、Claude が読むための文書の書き方
  - ワークフローとスクリプトが決まった文面で書く文(監査の通知の Issue など)
  - 今ある spec の本文の書き直し
- この spec が前提にしていること:
  - `/spec-review` は、今と同じく、審査役を動かす前に、点検役 `spec-style-checker` に spec の本文を点検させる
  - 所有者は、文を日本語で読む
  - この spec の PR は、スキルの手順とエージェントの定義を直すので、所有者が承認してからマージされる。スキルの手順とエージェントの定義は、所有者の承認が要る場所(`.claude/`)にある

## 要件

### 要件1 所有者に送る文の書き方の決まりを、リポジトリの1か所に置く

今は、書き方の決まりがメモリとスキルの手順に分かれていて、Claude がどれかを読み落とすと、同じ差し戻しが繰り返される。メモリは所有者の PC にしか無いので、ほかの人の PC の Claude は、所有者が差し戻した書き方を知らない。そこで、所有者は、Claude に、所有者に送る文の決まりを、リポジトリの1か所にまとめて置いてほしい。

1. Claude は、所有者に送る文の4つに共通の書き方の決まりを、リポジトリの中の1つのファイルに書く。この spec では、このファイルを書き方の決まりのファイルと呼ぶ。Claude は、所有者に送る文のどれを書くときも、書く前にこのファイルを読む。
2. Claude は、このファイルに、元の要望の節で所有者がわかりにくい文に入れると決めた種類を、すべて決まりとして書く。種類とは、「やりたいこと」の、所有者がこれまでに差し戻した種類の文を並べた箇条に挙げた種類と、「壁打ちで決めた、わかりにくい文の種類」でわかりにくい文に入れると決めた種類である。Claude は、メモリと会話の記録で所有者が差し戻した文の種類のうち、この2つに無いものも、決まりとして書く。
3. Claude は、決まりごとに、その決まりから外れた文の例と、直した文の例を書く。外れた文の例には、Claude が実際に送り、所有者が差し戻した文を、差し戻された前後の文も含めたまとまりで書く。直した文の例には、同じまとまりを決まりに沿って書き直した文を書く。所有者が差し戻した文が、メモリ、会話の記録、spec のファイルのどれにも残っていない決まりでは、Claude は、外れた文の例を自分で作り、Claude が作った例であることを、その例に書き添える。
4. Claude は、所有者がわかりにくい文に入れないと決めた次の書き方を、決まりから外れた書き方として書かない。
   - 「双方」「〜に限られる」「代替ではなく補完の関係にある」「失敗しうる」のような硬い言い回し
   - 1つの段落の中で太字をいくつも使うこと
   - 書いていないことまで読み取れてしまう文
   - 順番にすることに番号を振らない書き方
5. Claude は、このファイルに、決まりの例外として次のことを書く。所有者が画面で目にする名前(GitHub の「Re-run」など)は、画面と同じ綴りのまま書いてよい。ファイル名、コマンド、設定の名前は、元の綴りのまま書いてよい。所有者の言葉と Issue の本文と例の一覧から引用した部分は、引用元のまま書き、決まりに合わせて書き直さない。「起動: 30分ごと」のように「ラベル: 内容」の形で書く箇条書きでは、ラベルが主語や条件を示すので、内容の文の主語を省いてよい。
6. Claude は、`.kiro/settings/rules/spec-writing.md` の決まりのうち、元の要望の節で所有者が4つの文すべてに当てはめると決めた次の7つを、所有者に送る文の4つすべてに当てはめる。Claude は、この7つの決まりを `spec-writing.md` から書き方の決まりのファイルに移し、`spec-writing.md` には残さない。`spec-writing.md` のほかの決まりは、Claude は今と同じく spec の本文にだけ当てはめる。
   - 文ごとに主語と目的語を書く決まり
   - 番号だけで別の箇所を指さない決まり
   - 何を指すかが文の前後から決まらない言葉で文を済ませない決まり
   - まだ無い仕組みに名前を付けて主語にしない決まり
   - 英語と日本語を混ぜた決まり文句を使わない決まり
   - 専門用語の意味を書き添える決まり
   - 1つの文書で同じ決めごとを繰り返さない決まり
7. スキルの手順が定める報告の書式が、このファイルの決まりから外れるときは、Claude は、その書式をこのファイルの決まりに合わせて直す。たとえば、`/start` の判断の報告は、今は、観点ごとの根拠を表のマスに文で書く書式になっている。Claude は、この書式を、表には観点と当たるかどうかだけを書き、根拠を表の下に文で書く書式に直す。
8. このリポジトリは公開されている。Claude は、外れた文の例と直した文の例に、まだ直していないセキュリティの穴の中身と、秘密の値(パスワード、トークンなど)を書かない。

### 要件2 Claude は、所有者に送る文を、送る前に自分で読み直す

所有者は、毎回「わかりやすく書いて」と言わなくても、読める文が届くようにしたい。一方で、Claude が送る文を毎回別のエージェントに読ませると、費用がかかり、返事も遅くなる。そこで、所有者は、Claude に、送る前に書き方の決まりと照らして文を自分で読み直し、外れた文を直してから送ってほしい。

1. Claude は、チャットの報告と問い、Issue の本文、PR の本文を送る前に、書き方の決まりのファイルの決まりと照らして、その文を自分で読み直す。送る前とは、次の時を指す。
   - チャットの報告と問い: Claude がチャットの報告と問いを所有者に見せる前
   - Issue の本文: Claude が、起票する本文の案を所有者に見せる前と、Claude が Issue を起票する前と、Claude が Issue の本文に書き足す前
   - PR の本文: Claude が PR を作る前と、Claude が PR の本文を書き換える前
2. Claude は、読み直しで決まりから外れていると気づいた文を、すべて書き直してから送る。
3. Claude は、文を読み直すために、別のエージェントを動かさない。
4. Claude は、文を読み直したことを、そのたびに所有者に報告しない。所有者に送る文が、読み直しの話で長くならないようにするためである。
5. `spec-style-checker` は、spec の本文の決まりに加えて、書き方の決まりのファイルの決まりで spec の本文を点検する。`spec-style-checker` は、今と同じく、`/spec-review` の中でだけ動く。

### 要件3 所有者がこれまでに差し戻した文で、読み直しが働くことを確かめる

Claude が決まりを書いても、差し戻された文がどの決まりにも当たらないなら、Claude は読み直しで同じ文を見逃し、所有者に届く文は変わらない。また、直した文まで決まりから外れると判断されるなら、Claude は正しい文を書き直し続けることになる。所有者は、これまでに差し戻した文を使って、差し戻された文が決まりから外れると判断できることと、直した文が外れないと判断できることの両方を、Claude に確かめてほしい。

1. Claude は、所有者がこれまでに差し戻した文を集めて、例の一覧を作り、リポジトリに置く。Claude は、次の3つから文を集める。
   - Claude Code のメモリに書かれた差し戻しの例
   - Claude Code の会話の記録(2026-08-10〜2026-10-19)で、所有者が意味が分からないと差し戻した文
   - 元の要望の節の「壁打ちで決めた、わかりにくい文の種類」で、わかりにくい文に入れると決めた種類の例
2. Claude は、例の一覧の文ごとに、差し戻された文と、Claude が決まりに沿って書き直した文を並べて書く。差し戻された文が、メモリ、会話の記録、spec のファイルのどれにも残っていないものは、Claude は一覧に入れない。
3. この spec の PR を出す前に、Claude は、例の一覧のすべての文を、書き方の決まりのファイルの決まりと照らして自分で読み直す。このとき、Claude は、例の一覧の文を、引用した文としてではなく、Claude が送る文として読む。差し戻された文は、どれも、書き方の決まりのファイルのどれかの決まりから外れると判断できることを確かめる。書き直した文は、どの決まりからも外れないと判断できることを確かめる。Claude は、文ごとに、差し戻された文が外れる決まりの名前と、書き直した文が外れないことを、PR の本文に書く。
4. 差し戻された文のうち、どの決まりから外れるとも判断できない文があれば、Claude は、書き方の決まりのファイルの決まりと例を直して、確かめ直す。書き直した文のうち、どれかの決まりから外れると判断した文があるときも、Claude は、同じく書き方の決まりのファイルの決まりと例を直して、確かめ直す。
5. 書き方の決まりのファイルの決まりを変える PR を出すたびに、Claude は、例の一覧のすべての文で、この spec の PR のときと同じ確かめと、決まりと例の直しをやり直し、結果を PR の本文に書く。
6. Claude は、この確かめのために、別のエージェントを動かさない。

### 要件4 所有者がわかりにくい文を指摘したら、Claude はその文を例として決まりに足す

所有者が差し戻した文が決まりに足されなければ、Claude は、送る前の読み直しで、同じ種類の文を次も見逃す。所有者は、自分が一度差し戻した文を、Claude が二度と送らないようにしてほしい。

1. 所有者が、Claude が送った文をわかりにくいと指摘したら、Claude は、その文を書き直して送り直す。そのあとに、Claude は、指摘された文と書き直した文を、書き方の決まりのファイルに例として足し、例の一覧にも足す変更を作る。
2. 指摘された文が書き方の決まりのファイルのどの決まりにも当たらないときは、Claude は、その種類の文を差し戻す決まりも足す。指摘された文が今ある決まりに当たるときは、Claude は、その決まりに例だけを足す。
3. Claude は、この変更を、そのとき進めている作業の PR に混ぜず、別の PR で出す。この PR は、ほかの PR と同じく、品質のチェックを通れば、所有者の承認を待たずに自動でマージされる。そのため、Claude は、書き方の決まりのファイルと例の一覧を、所有者の承認が要る場所(`.github/CODEOWNERS` に書かれた場所)の外に置く。Claude は、決まりと例を、エージェントの定義とスキルの手順に写さない。写すと、例を足す PR が所有者の承認が要る場所を直すことになるためである。
4. Claude は、この PR を出したことを、PR の番号を添えて、チャットで所有者に1文で知らせる。

### 要件5 メモリにある書き方の決まりを、リポジトリに移してメモリから消す

書き方の決まりがメモリとリポジトリの両方に残ると、2つが食い違ったときに、Claude はどちらに従えばよいか分からなくなる。そこで、所有者は、Claude に、メモリにある書き方の決まりを、リポジトリに移したうえでメモリから消してほしい。

1. Claude は、所有者の PC の Claude Code のメモリのうち、所有者に送る文の書き方の決まりを書いたものを、すべて書き方の決まりのファイルに移す。書き方の決まりとは、どんな言葉を使うか、何を書くか、どの順で書くかの決まりを指す。
2. この spec の PR がマージされたあとに、Claude は、移した決まりをメモリから消す。メモリのファイルに、書き方の決まりのほかのこと(作業の進め方など)も書かれているときは、Claude は、書き方の決まりの部分だけを消し、ほかの部分を残す。Claude は、メモリの目次(MEMORY.md)の行も、消したファイルに合わせて消す。
3. Claude は、消したメモリのファイルと、残した部分があるメモリのファイルの一覧を、所有者に示す。
