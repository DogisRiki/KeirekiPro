# タスク

## 完了条件(全タスク共通)

Claude は、各タスクを終えたと判断する前に、次のすべてを満たす。

1. Claude は、タスクが満たす受入基準と、その受入基準を確かめる手段(テストの名前、または確かめの手順)の対応を、タスクの箇条書きに書く。確かめる手段の無い受入基準を残さない
2. この spec は、frontend・backend・terraform のどれも変えない。そのため、Claude は verify の Skill を走らせる代わりに、各タスクの「完了の確かめ方」を行う
3. Claude は、テストのskip化、アサーションの削除、カバレッジやlintの除外の追加で、完了条件を満たしたことにしない
4. Claude は、新しいテストを書いたら、対象の判定を一時的に壊してそのテストが失敗することを確かめ、壊した判定を元に戻す
5. Claude は、この spec の実装を、メインの作業ツリーではなく、origin/main から作った別の作業場所(git worktree)で行う。メインの作業ツリーは、別の会話が別のブランチで使っているからである。この spec のディレクトリ `.kiro/specs/spec-readable-writing/` は、メインの作業ツリーにコミットされないまま置かれている。そこで、Claude は、作業場所を作ったらすぐに、このディレクトリをメインの作業ツリーから作業場所に写す。タスク3.1・4.2・6.1が直す行(`/kiro-spec-init` の追加の要望の目印、`/spec-review` の Step 6、CLAUDE.md の「Issueの印」の節)は、#475 で origin/main に入っている

## 実装のメモ

- この spec の実装中に動く `/kiro-impl` は、タスク5.1で直す前のものである。直す前の `/kiro-impl` は `_Depends:_` と `_Blocked:_` と `## Implementation Notes` の名前を読み書きする。そこで、この spec の実装では、Claude はタスクを番号の順に1つずつ進め、`_依存:_` に挙げたタスクが終わっていることを自分で確かめる。Claude は、保留の理由と実装中に分かったことを、`## Implementation Notes` ではなく、この節に書く
