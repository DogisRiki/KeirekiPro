# タスク

## 完了条件(全タスク共通)

Claude は、各タスクを終えたと判断する前に、次のすべてを満たす。

1. **受入基準の引用とテストの対応付け**: 各タスクは、対応する requirements.md の受入基準を引用し、それを確かめる手段(実機確認の項目番号)をタスクの箇条書きに持つ
2. **verify の実行**: 変更領域が `.claude/` と `.kiro/` と `CLAUDE.md` / `README.md` だけなので、既存の verify Skill(frontend / backend / terraform)は対象外である。**Claude は、代わりに、design.md のテストの方針の節に定めた実機確認(項目1〜12)を行い、結果を記録する**(フックはシェルスクリプトで、入力がJSON、副作用がファイルなので、既存のテストの器が無い)。この項目は、タスク1〜7 に当てはめる(#559 で変更)
3. **ゴールハック禁止**: Claude は、実機確認の項目を減らすこと、確認せずに完了とすること、検知の条件を緩めて通すことのどれもしない
4. Claude は、新規のフックについて、止まるべき状態を実際に作って止まることを確かめてから、通るべき状態で通ることを確かめる
5. Issue #559 のために足したタスク(題名の末尾に `(#559)` があるもの)では、Claude は、design.md のテストの方針の節の「確認(#559 で足したもの)」の項目のうち、項目16 をタスク10 で、項目17〜20 と22 をタスク11.1 で、項目21 をタスク11.2 で行う。タスク8〜10 を終えたかどうかは、Claude は、そのタスクの「完了の確かめ方」で判断する。(#559)
