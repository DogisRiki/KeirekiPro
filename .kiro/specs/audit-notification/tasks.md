# Implementation Plan

## KeirekiPro 完了条件(全タスク共通)

1. **acceptance criteria の引用とテスト対応付け**: 各タスクは、対応する requirements.md の受入基準と、それを検証するテスト(`.github/scripts/tests/` 配下のファイル名)を detail に持つ。テストが無い受け入れ基準を残さない。ワークフローと文書のタスクは、設計の契約との突合で確認する
2. **verify の実行**: 変更領域は `.github/`・`doc/`・`README.md`・`.kiro/` のみのため、既存の verify Skill(frontend / backend / terraform)は対象外。代わりに、guardrails.yaml と同じ検査を手元で通す
   - 同梱テスト: ホストで直接実行しない(ホストに jq が無く、赤を期待するテストが誤った理由で通るため)。alpine コンテナへコピーし、実行ビットを外して `bash` で起動する
   - shellcheck: `.github/scripts` のシェルスクリプトに `koalaman/shellcheck:v0.11.0` を流す
   - actionlint: ワークフローに `rhysd/actionlint:1.7.12` を流す(ワークフロー内の `run:` にも shellcheck がかかり、info / style も失敗扱いになる)
3. **ゴールハック禁止**: テストのskip化・アサーション削除で完了条件を満たさない。判定不能ケースの期待終了コードを 1 から 2 に変えるのは設計で決めた契約変更であり、PR本文の `Test-Change-Justification` に理由を記載する
4. 新規テストは対象コードを一時的に壊して赤くなることを確認してから戻す
5. **着手前の前提**: `.github/` 配下の編集は `.claude/settings.json` で禁止されている。タスク1.1〜3.3に着手する前に、人間に禁止の一時解除を依頼し、解除を確認してから始める。出荷後は人間が元に戻す

## Implementation Notes

- (1.1) コンテナでのテストは `apk add bash jq coreutils` とする。alpine の busybox 版 date は ISO 8601(`2026-01-02T00:00:00Z`)を読めず、変更前のスクリプトでも失敗する。CI は ubuntu(GNU date)なので影響しない
- (1.1) bash の算術展開のエラー(`08` のような先頭0・非数値・unbound variable)は ERR トラップを通らず終了コード1で止まる。算術に入る外部由来の値(引数・環境変数)は `^[1-9][0-9]{0,N}$` の形で先に検査して exit 2 にする。1.2〜1.4 でも同じ形を使う
- (1.3) `set -E`(errtrace)が無いと、関数の中の失敗が ERR トラップを通らず終了コード1になる(alpine の bash で実測)。関数内の失敗を再現するテストには、報告先 GITHUB_STEP_SUMMARY をディレクトリにする手が使える
- (1.4) `[ "$(cmd)" = x ]` のように比較式の中に置いたコマンド置換は、失敗しても set -e も ERR トラップも効かず空文字として比較に流れる。失敗しうる取り出しは比較の前に変数へ代入する
- (2.1) `gh issue create --assignee` は担当者を解決できないと起票そのものが失敗しうる(レビューでの指摘)。2.2 の読み戻しの設計で扱いを確かめる
- (2.2) 担当者は起票の後に REST(POST …/assignees)で追加し、応答を読み戻す。付かない・失敗は警告のみで exit 0。design.md の AuditIssue の記述もこれに合わせた
- (2.2) 通知の本文は監査手順書の「監査の通知Issueを受けたとき」節を名指しする。4.1 ではこの見出しをそのまま使い、5 の突合で一致を確かめる
- (2.2) 本文は `--body-file` で渡す。多バイト60,000字は引数1つの上限(128KiB)を超えるため
- (2.1/2.2) 2.1 のテストの担当者欄の期待値を変えた。PR本文の `Test-Change-Justification` に記載する
- (3.1) ステップの本文を取り出して動かす使い捨ての検査スクリプトは、ステップ名(Judge / Test notifier / Notify / Conclude)で取り出す。3.2 でも同じ名前にそろえる。報告ファイルは `${RUNNER_TEMP}/audit-report.md` を Judge と Notify で共有する
- (3.1) Judge は既定の `bash -e` を `set +e` で打ち消し、最後に `exit 0`。後続は `always()`。キャンセル時も判定不能として通知される(故障を知らせる目的に沿うため許容)
