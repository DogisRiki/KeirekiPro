# 要件

## 元の要望
Issue #577: spec の要らない Issue の着手で、判断と観点ごとの理由を見せずに実装を始める

### きっかけ

#568 の開発(PR #574)の振り返りで AI が見つけ、所有者が起票を決めた。

### 困っていること

- #568 で、CLAUDE.md を変えたあとも Claude が決まりどおり動くかを、新しい Claude に `/start` を打たせて確かめた。spec の要らない Issue で、Claude は判断と観点ごとの理由の表を見せずに実装に入った。たとえば「Spec 無し・問い無しの判断です。ブランチを作って実装に入ります。」の1文だけで実装を始めた。CLAUDE.md を変える前の文書でも同じだった。(AIの提案を了承)
- 所有者のふだんの着手では、表が出なかったことは無い。

### やりたいこと

- 何が原因かを調べるところから始める。

### 決めた方式

- spec を作らずに実装すると判断し、所有者に尋ねる問いも無いときも、AIは判断と観点ごとの理由の表を見せたところで止まり、所有者の返事を受けてから実装を始める。判断が誤っていると所有者が思ったときに、方向を変えるよう指示できるようにするため。

## はじめに

`/start` で spec が要らず、所有者に尋ねる問いも無いと判断したとき、今の Claude は、判断と観点ごとの理由の表を見せたら、所有者の返事を待たずに実装を始める決まりになっている。ところが、#568 の確かめで Claude が別の Claude に `/start` を打たせたとき、着手した Claude は表を見せずに実装を始めた。表が見えないと、所有者は判断の誤りに気づけず、方向を変えるよう指示できない。

この spec では、Claude は、着手した Claude が表を見せなかった原因を調べて記録に残す。あわせて、Claude は、spec が要らず問いも無いときの着手の進み方を変える。

## 範囲

- この spec で決めること: `/start` で「spec を作らずに実装する」と判断し、所有者に尋ねる問いが無いときに、Claude が止まることと、所有者の返事を受けたあとの Claude の進み方。この進み方を説明している文書の記述。表が出なかった原因の記録。表を返答の本文に書く前に Claude がファイルを書き換えると止める仕組みを、残すか取り除くか
- この spec で決めないこと: 4つの観点の定義と、spec が要るかどうかの決め方。問いがあるときの進み方(今も、Claude は答えを受けてから実装を始める)。spec が要るときと、Issueを分けるときの進み方(今も、Claude はコマンドを打つ依頼か分け方の了承を求めて止まる)。実装の途中で見立てが外れてIssueを小さく分けるときに、Claude が返事を待たずに部分のIssueを起票すること
- この spec が前提にしていること: `/start` の着手のときに書かれる着手の予約により、Claude が所有者の返事を待つ間も、ほかのセッションはそのIssueを作業中として扱う

## 要件

### 要件1 表が出なかった原因を調べて残す

Issueの本文は、判断と観点ごとの理由の表が出なかった原因を調べるところから始めると決めている。Claude が原因を調べずに着手の進め方だけを変えると、表が出ない場面がほかに残っていても、所有者も Claude もそれに気づけない。

1. Claude は、spec が要らず問いも無い着手で、判断と観点ごとの理由の表が出なかった原因を調べる。Claude が調べる材料は、#568 の確かめで表が出なかったときの記録と、#568 の確かめと同じ条件(所有者の画面を通さずに、Claude が別の Claude に `/start` を打たせる条件)で着手させた試しの結果と、所有者のこれまでの着手の会話の記録である。
2. Claude は、表が出なかった着手と表が出た着手の条件を比べ、どの違いが表の有無を分けたかを、spec の調査の記録(research.md)に書く。Claude は、原因を確かめた根拠も同じ記録に書く。根拠とは、どの会話の記録やどの試しで何が起きたかを指す。
3. 原因のうち確かめられなかった点があれば、Claude は、確かめられなかったことと、その理由を同じ記録に書く。

### 要件2 spec が要らず問いも無いときも、表を見せて止まる

所有者は、表を読んで判断が誤っていると思ったときに、方向を変えるよう指示したい。Claude が返事を待たずに実装を始めると、所有者が表を読む前に実装が進み、方向を変える機会が無くなる。そこで、spec が要らず問いも無いときも、Claude は表を見せたところで止まる。

1. `/start` で「spec を作らずに実装する」と判断し、所有者に尋ねる問いが無いときは、Claude は、判断と4つの観点ごとの理由の表を、所有者に見える返答の本文に書く。Claude は、表を書いたところで止まり、所有者の返事を待つ。
2. 所有者が返事をするまで、Claude は実装を始めず、Issueを直すためにファイルを書き換えない。
3. Claude は、表の前に置く「してほしいこと」に、所有者への依頼として次の2つを書く。1つは、所有者が判断を読んでよいと思ったら、進めてよいと返事をすること。もう1つは、所有者が判断をおかしいと思ったら、どう進めるかを返事に書くこと。
4. Issueが小さく直し方が明らかなときも、Claude は、表を返答の本文に書いて止まる。
5. すでに spec がある機能を spec を作らずに直すと判断したときも、Claude は、表を返答の本文に書いて止まる。
6. Claude が、#568 の確かめと同じ条件で、別の Claude に、Issueが小さく直し方が明らかな着手を3回させたとき、3回とも、着手した Claude はファイルを書き換える前に表を返答の本文に書き、所有者の返事を待つところで返答を終える。Claude は、このことを着手した Claude の会話の記録で確かめる。この条件を使うのは、表が出なかった側の条件で確かめるためである。

### 要件3 所有者の返事の中身で進み方を決める

Claude が止まるのは、所有者が判断を確かめ、必要なら方向を変えられるようにするためである。そこで、Claude は、所有者の返事が進めてよいという返事か、別の進め方の指示かで、進み方を変える。

1. 所有者が進めてよいと返事をしたら、Claude は実装を始め、品質チェックを通して出荷まで進める。Claude は、出荷までの間に、所有者に改めて進めてよいかを尋ねない。ただし、実装の途中で4つの観点を当て直して所有者に尋ねる問いが出たときは、Claude は問いを出して止まる。また、実装の途中で spec を作る進め方に切り替えるときは、Claude は spec を始めるコマンドを打つよう依頼して止まる。
2. 所有者が判断の誤りを指摘したか、別の進め方を指示したら、Claude は実装を始めない。Claude は、所有者の指示に沿って進め方を決め直し、決め直した判断を、判断と観点ごとの理由の表の書式で示す。
3. 決め直した判断が、また「spec を作らずに実装する」で問いも無いときは、Claude は、表を返答の本文に書いて止まり、所有者の返事を待つ。
4. 所有者の返事が、表の中身についての質問か、着手と別の話のときは、Claude はそれに答え、実装を始めずに所有者の返事を待ち続ける。Claude は、進めてよいかの答えを催促しない。
5. 所有者の返事が、着手の進め方についての返事に見えるが、進めてよいという返事とも別の進め方の指示とも決められないときは、Claude は実装を始めない。Claude は、進めてよいか、どう進めるかを、所有者に尋ね直す。

### 要件4 着手の進み方を説明する文書をそろえる

CLAUDE.md と README には、spec が要らないときは返事を待たずに実装すると書いてある。この記述が残ると、Claude と所有者は、実際の動きと違う進み方を読むことになる。

1. Claude は、着手の進み方を説明する文書(CLAUDE.md、README、`.claude/skills/start/SKILL.md`)から、spec が要らず問いも無いときに返事を待たずに実装するという記述を無くす。Claude は、その箇所を、表を見せて所有者の返事を待つという記述にそろえる。
2. Claude は、spec が要らないときに所有者が何もしない流れを描いた箇所も、所有者が判断を読んで返事をする流れにそろえる。この箇所には、README の進み方の図と、人間が手を動かす箇所の数の記述と、CLAUDE.md と README の人間が関与することの一覧を含む。
3. README の、どの観点にも当たらないときの進み方の説明では、Claude は、所有者が判断を読んで、進めてよいか別の進め方かを返事することを書く。

### 要件5 表を書く前の書き換えを止める仕組みを、残すか取り除くかを決める

Claude は、#577 で表が出なかった原因を調べる途中で、着手の報告(判断と観点ごとの理由の表)を返答の本文に書く前に Claude がファイルを書き換えると止める仕組みを作った。この仕組みの説明の文と、止めるときに Claude に返す文は、返事を待たずに実装する今の進み方を前提にしている。表を見せて止まる進み方に変えたあとも、この仕組みが要るかを、Claude は試しの結果で決める。

1. Claude は、#568 の確かめと同じ条件で別の Claude に Issueが小さく直し方が明らかな着手を3回させる試しを、この仕組みを外した状態で行う。
2. 3回とも、着手した Claude がファイルを書き換える前に表を返答の本文に書き、所有者の返事を待つところで返答を終えたら、Claude はこの仕組みを取り除く。
3. 3回のうち1回以上で、着手した Claude が表を返答の本文に書く前にファイルを書き換えようとし、残りの着手では、着手した Claude がファイルを書き換える前に表を書いて所有者の返事を待つところで返答を終えたら、Claude はこの仕組みを残す。Claude は、仕組みの説明の文と、止めるときに Claude に返す文を、表を書いたら止まって所有者の返事を待つ進み方にそろえる。Claude は、仕組みを残した状態で、#568 の確かめと同じ条件で別の Claude に Issueが小さく直し方が明らかな着手を3回させる試しをやり直す。
4. 3回の着手で着手した Claude がしたことが、仕組みを取り除くときの動きにも、仕組みを残すときの動きにも当たらないときは、Claude は仕組みを残すか取り除くかを自分で決めない。当たらない動きには、着手した Claude が表を書かずに返答を終えた着手、表の一部だけを書いた着手、表を書いたあとに所有者の返事を待たずにファイルを書き換えた着手、spec が要るか所有者に尋ねる問いがあると判断した着手を含む。仕組みを残した状態でやり直した3回のうち1回でも、着手した Claude がファイルを書き換える前に表を書いて所有者の返事を待つところで返答を終えなかったときも、Claude は自分で決めない。
5. Claude は、仕組みを残すか取り除くかを自分で決めないときは、合格と書かず、着手した Claude が3回の着手でしたことを所有者に報告する。仕組みを残すか取り除くかは、所有者が決める。所有者が決めるまで、Claude は出荷しない。
