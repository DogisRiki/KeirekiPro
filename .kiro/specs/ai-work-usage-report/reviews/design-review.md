### 申告

**1. 蓄積の一覧を、決まった題名の閉じた Issue の本文と、300行ごとの区切りのコメントに置く** — 「github.pl」の「一覧の Issue」「一覧の行の書き方」、research.md の「Decision: 蓄積の一覧の置き場」

- Issue の記載: 「蓄積した集計は GitHub 上で見られるようにする」「蓄積の一覧に1行増える」だけで、置き場は書かれていない
- 決めたこと: 題名「AIの作業の集計の一覧」の Issue を作ってすぐ閉じ、行を本文と区切りのコメントに書く。同時の書き込みは、書いたあとに読み直して足し直す。直す案の索引も同じ本文の末尾に置く
- 他にありえた選択肢: GitHub Projects v2(並べ替えと絞り込みの画面があるが `project` の権限が要る)、専用のブランチの Markdown のファイル、Issue ごとのコメントだけを置いて一覧を作らない
- 外れていた場合: 一覧の形と置き場は、集計のコメントの印(`keirekipro-usage-*:v1`)と、過去の行との比べと、会話の始めのフックの確かめが前提にしている。あとで置き場を替えると、それまでの行を移す作業と、読む側のすべての部品の直しが要る

**2. 手元の記録を、git の共通ディレクトリの下(`keirekipro-usage/`)に置き、PC どうしで同期しない** — 「全体の構成」、「データの形」の「手元の記録」

- Issue の記載: なし
- 決めたこと: 会話の記録から抜き出した数と印と道具の時間を、clone ごとの git の共通ディレクトリの下に置く。worktree を消しても残るが、clone(本体の作業フォルダ)を消すと消える
- 他にありえた選択肢: ホームディレクトリの下(`~/.claude/` の外)に、リポジトリごとの置き場を作る。GitHub に数だけを途中で送る
- 外れていた場合: 本体の作業フォルダを消すか clone し直すと、30日を過ぎた会話の数が戻らず、その Issue の集計が小さく出る(注記は付く)。置き場を替えるには、抜き出しと集計と会話の始めのフックのすべてを直す

**3. Issue ごとの集計を、その Issue のコメントとして書き、さかのぼりの集計では過去の閉じた Issue すべてにコメントを書く** — 「usage.sh」の `backfill` の手順3、「github.pl」の `publish`

- Issue の記載: 「その Issue の集計が GitHub 上で見られ」まで。どこに書くかは書かれていない
- 決めたこと: 集計は Issue のコメントに置く。さかのぼりでは、この PC に記録が残る過去の Issue(research.md によれば最近3か月だけで122件)のそれぞれにコメントを書く
- 他にありえた選択肢: 集計の本文を一覧の Issue の区切りのコメントにまとめて置き、元の Issue には書かない。さかのぼりの分だけ一覧の Issue にまとめる
- 外れていた場合: さかのぼりの集計の1回で、閉じた Issue に百件を超えるコメントが付き、その Issue を見ている人に通知が出る。あとで置き場を替えると、印でコメントを探す `reported` の決まりも替わる

**4. 応答の終わりのあと、human でない行(背景のコマンドの知らせ、CI の見張りの知らせ、予約した起こし)までの時間を、作業時間の「待ち」に入れる** — 「処理の流れ」の2つ目の図と、その下の箇条

- Issue の記載: 「そのうち待ち時間: AIの作業時間のうち、CI や品質チェックが終わるのを待っていた時間」
- 決めたこと: 応答を終えて止まっている会話が、背景の仕事や予約した起こしで再び動くまでの時間を、すべて作業時間(待ち)に数える
- 他にありえた選択肢: 予約した起こし(`scheduled`)までの時間は作業時間に入れない。または上限の時間を設ける
- 外れていた場合: Claude が1時間先に起こしを予約して止まった時間も、AI の作業時間に入る。所有者が見る作業時間が、実際に動いた時間より大きく出る

**5. GitHub に書けなかったとき、同じ会話の中では再試行せず、次の会話の始めまで出し直さない** — 「usage.sh」の「失敗したとき」、「失敗したときの扱い」

- Issue の記載: なし
- 決めたこと: gh の一時的な失敗でも、出し直しは次の会話の始めのフックの知らせから行う
- 他にありえた選択肢: 数回の再試行を入れる
- 外れていた場合: 一時的な失敗のたびに、その会話では集計が出ず、所有者は次の会話まで集計を見られない

**6. `.claude/settings.json` に、フックの登録5つと `permissions.allow` の1行を足す(ゲートの設定の変更)** — 「settings.json の変更」、「移行」

- Issue の記載: なし
- 決めたこと: `Stop` `SubagentStop` `SessionEnd` `PostToolUse` `SessionStart` にフックを足し、`Bash(bash .claude/scripts/usage/usage.sh *)` を許可に足す。完成版は置き場所に作り、所有者が置く
- 他にありえた選択肢: 許可を足さず、Claude が呼ぶたびに権限の確認を出す
- 外れていた場合: 許可の行で、usage.sh のどのサブコマンドも確認なしに動く。`PostToolUse`(matcher `*`)のフックは、すべての道具の呼び出しのたびに動く

**7. 所見の「目立つ点」を、過去の行の中央値に対する倍率が1.5以上か0.67以下の値とする** — 「usage-report のスキル」の手順2

- Issue の記載: 「過去と比べて目立つ点の所見を添える」
- 決めたこと: 作業時間・トークン数・使用料・spec へ戻った回数の4つを、過去の全行の中央値と比べる
- 他にありえた選択肢: spec の有無ごとに分けて比べる。直近の N 件だけと比べる
- 外れていた場合: spec あり と spec 無しの Issue を同じ中央値と比べるので、spec ありの Issue はいつも「目立つ」と書かれやすい。比べ方は所見の文の中だけなので、あとから直しやすい
