## tasks の生成のときの点検による design の直し(2026-10-12)

`/kiro-spec-tasks` の組み立ての点検が、design のテストの方針の誤りと抜けを見つけ、design に戻した(RETURN_TO_DESIGN)。次を直した。

| 点検の指摘 | 直したこと |
|---|---|
| 起動の確かめに使う `ci.yaml` は `workflow_dispatch` を持たない | `auto-merge.yaml` に替えた |
| 承認(pending_deployments)と取り消しの確かめが無い | 所有者が `terraform-apply.yaml` を起動して承認を待つあいだに、Claude の鍵と所有者の PAT で承認を試して 403 を見て、所有者が Reject する項目と、取り消しの項目を足した |
| 要件6の2(ワークフローのファイルを変えた PR を作れる)の確かめが無い | コメントだけを変えたブランチで PR を作る項目を足し、同じ PR で所有者の PAT の承認が拒まれることも見るようにした |
| `PowerUserAccess` はサービスにひもづくロールの作成と削除を許し、要件3の6と合わない | `PowerUserAccess` の公式の定義(2026-10-12 に確かめた v12)で事実を確かめた。`keirekipro-ops-guard` で `iam:CreateServiceLinkedRole` と `iam:DeleteServiceLinkedRole` も Deny するようにし、確かめの項目に IAM のロールの作成を足した |
| シェルのテストを流す場所が既存のテストと食い違う | ホストの Git Bash で流すと決めた |
