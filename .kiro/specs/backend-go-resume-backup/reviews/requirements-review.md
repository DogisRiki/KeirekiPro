### 申告

**1. バックアップのファイルの文字の書き方を、Java 版と1文字ずつ同じにする** — 要件3の受入基準3、要件6の受入基準2の後半、要件8の受入基準1の2つ目

- Issue の記載: 置き換えの spec の 11.2「書き出すバックアップの形を同じにする」を満たす、とだけある。文字の書き方には触れていない
- 決めたこと: `<` `>` `&` と行や段落の区切りの文字を、Java 版と同じ書き方にする。比べる検査とは別の機械の確認を設計で作る
- 他にありえた選択肢: 置き換えの spec の調べたこと(research.md 155-160行)は、画面は JSON を読んでから使うので利用者から見た違いは無い、とした。書き方の違いを、利用者が目にしない違いとして変えた動きの一覧に載せ(置き換えの spec の 9.5 と 9.6)、Go の標準の書き方のままにする案もある
- 外れていた場合: 所有者が同じでなくてよいと考えていたなら、Go の標準と違う JSON の書き手と、別の確認の道具を作る手間が無駄になる。逆に、所有者が同じにしたかったのに外していたら、利用者は手元のファイルを開いたときに `<` のような書き方を見る

**2. 退会してすでに居ない利用者の要求で Java 版が 500 を返すとき、Go 版は 400 か 404 で答える** — 要件5の受入基準3、要件1の受入基準2の2つ目

- Issue の記載: なし。認証の spec の要件2の受入基準3は「Java 版と同じにする」とし、置き換えの spec の 4.4 は、画面が送る要求には Java 版と同じ答えを返すとする
- 決めたこと: マスタと経歴書の spec の CB-049 と同じく、Java 版の 500 を 400 か 404 に変え、変えた動きの一覧に載せる
- 他にありえた選択肢: 画面が送りうる要求なので、Java 版と同じ 500 を返す
- 外れていた場合: 退会した利用者が別のタブで戻しを押したとき、画面に出るものが、決まったサーバの誤りの知らせから、答えの本文の文言に変わる。どちらでも戻しは終わらないので、手戻りは小さい
