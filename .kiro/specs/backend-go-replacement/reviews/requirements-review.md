**1. 画面が送る要求で Java 版と同じにできない違いを、所有者が受け入れれば、Issue #445 の本文と要件9の受入基準8を直さずに、変えた動きの一覧に載せるだけで、Java 版と同じにする受入基準から外す** — 要件9の受入基準9、要件4の受入基準4・6、要件9の受入基準2

- 決めたこと: Claude は自分の判断では変えず、違いと理由を所有者に示す。所有者が受け入れた違いは、どこが変わるかと受け入れた日を添えて変えた動きの一覧に載せ、その違いでは Go 版は一覧の動きに従う。Issue #445 の本文と requirements には、受け入れた違いを1つずつ書き足さない
- 他にありえた選択肢: 受け入れた違いを、そのつど Issue #445 の決めた方式と要件9の受入基準8に書き足す(requirements の承認をし直す)。または、画面が送る要求では違いを受け入れず、必ず Go 版を Java 版に合わせる
- 外れていた場合: 所有者が、利用者に見える違いは Issue と requirements に書いて残すことを求めていたなら、すでに一覧にある CB-043〜CB-046 を含めて、受け入れた違いを Issue と受入基準8に書き写し、requirements を承認し直すことになる。今の形では、requirements だけを読んでも、利用者に見える違いが何件あるかは分からず、所有者は切り替えの出荷の前に一覧を見て確かめる(要件9の受入基準6)
