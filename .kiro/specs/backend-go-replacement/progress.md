## 所有者がする操作

所有者がこの置き換えでする操作は、原則として次の6つである。

1. spec の各段階のコマンドを打つことと、各段階の承認
2. ゲート設定を変える PR と、所有者の承認が要るほかの PR の承認
3. 本番の設定の変更の反映(`terraform-apply.yaml` を、`plan_only` を付けて1回、外して1回動かす)
4. 切り替えの出荷と、Java 版に戻す出荷
5. 切り替えのあとに、画面で確かめること
6. Java 版を消してよいかの判断

6つのほかの操作が要ると分かったときは、Claude は、その操作が要る理由と、Claude が自分でできない理由を添えて、所有者に頼む。

## PR の本文の決まり

- この spec の PR の本文には、`Spec: .kiro/specs/backend-go-replacement` と `Refs: #445` を書く
- まとまりの spec の PR の本文には、そのまとまりの spec を指す `Spec: .kiro/specs/<名前>` と、そのまとまりの子の Issue を指す行を書く
- 所有者の承認が要る PR の本文には、「承認が要る理由」と「main に入れたときに本番で起きること」の2つの欄を書く。PR を作ったときの所有者への返事に、この2つの欄をそのまま写す。本番で何も起きない PR では、2つ目の欄に「本番で起きることは無い」と書く
- 段階3から Java 版を削除するまでは、Java 版か Go 版の一方の動きを直す PR で、もう一方にも同じ機能があれば、同じ PR でもう一方も同じように直す
- Issue #445 を閉じるのは、段階6の作業をすべて終えた PR だけである。それより前の PR では `Closes #445` を書かない

次のときは、Claude は作るのを止め、所有者に報告する。どう扱うかは所有者が決める。
