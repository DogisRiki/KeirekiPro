# 要件

## 元の要望
Issue #499: プロジェクトとポートフォリオの「概要」などに、256文字以上を保存できない

### きっかけ

2026-10-06、#481 の確認に使う小さな不具合をAIがアプリから探して見つけ、所有者が起票を指示した。

### 困っていること

- プロジェクトの「概要」「役割」と、ポートフォリオの「概要」は、画面とAPIでは1000文字まで入力できるが、256文字以上を入れると保存できない。

### どうなれば解決か

- プロジェクトの「概要」「役割」と、ポートフォリオの「概要」に、1000文字まで保存できる。(AIの提案を了承)

## はじめに

職務経歴書のプロジェクトの「概要」「役割」と、ポートフォリオの「概要」について、アプリは入力の検査で1000文字までの文章を認めている。ところが、アプリが文章をしまう先は255文字までしか受け付けない。そのため、利用者が256文字以上の文章を入れると、アプリは入力の検査を通したあとで保存に失敗する。利用者は、画面で1000文字まで書けると受け取るので、書いた文章が保存できない理由が分からない。

この spec は、アプリが入力の検査で認めた1000文字までの文章を、そのまま保存できるようにする。

## 範囲

- この spec で決めること: プロジェクトの「概要」「役割」と、ポートフォリオの「概要」の3つの欄に、アプリが1000文字までの文章を保存できること。あわせて、アプリが今の入力の検査と、すでに保存してある文章を変えないこと
- この spec で決めないこと: 3つの欄の上限の文字数(1000文字)を変えること。ほかの欄(会社名、プロジェクト名、チーム構成、ポートフォリオ名、リンクなど)の上限を変えること。入力欄の見た目を変えることと、残りの文字数の表示を足すこと。PDF と Markdown の出力の見た目を変えること
- この spec が前提にしていること: アプリの入力の検査は、3つの欄に1000文字までの文章を認め、1000文字を超える文章をエラーにしている

## 要件

### 要件1 1000文字までの文章を保存できる

利用者は、アプリが入力の検査で認めた文章は保存できるものと受け取る。そこで、アプリは、入力の検査で認めた3つの欄の文章を、長さを理由に失敗させずに保存する。

1. 利用者がプロジェクトの「概要」に、アプリの入力の検査が認める長さ(1000文字まで)の文章を入れて保存したら、アプリは、その文章を1文字も欠かさずに保存する。
2. 利用者がプロジェクトの「役割」に、アプリの入力の検査が認める長さ(1000文字まで)の文章を入れて保存したら、アプリは、その文章を1文字も欠かさずに保存する。
3. 利用者がポートフォリオの「概要」に、アプリの入力の検査が認める長さ(1000文字まで)の文章を入れて保存したら、アプリは、その文章を1文字も欠かさずに保存する。
4. アプリは、3つの欄の文章を、次のどの保存のしかたでも同じく保存する。項目を新しく足して保存するとき、すでにある項目を直して保存するとき、自動保存で保存するとき、職務経歴書をコピーして新しく作るとき、バックアップから復元するとき。
5. 利用者が3つの欄に1000文字ちょうどの文章を保存したあとで職務経歴書を開き直したら、アプリは、保存した文章を画面にそのまま表示する。アプリは、その職務経歴書のバックアップ、PDF の出力、Markdown の出力にも、保存した文章を欠かさずに載せる。

### 要件2 1000文字を超える文章は今までどおりエラーにする

上限の文字数は、所有者が決めた1000文字のままにする。保存できる長さを広げても、アプリが1000文字を超える文章を受け付けるようになってはいけない。

1. 利用者が3つの欄のどれかに1000文字を超える文章を入れて保存しようとしたら、アプリは、今と同じエラーの文(例: 「プロジェクト概要は1000文字以内で入力してください。」)を出し、その文章を保存しない。

### 要件3 すでに保存してある文章を変えない

利用者がこれまでに保存した職務経歴書の内容は、この変更のあとも同じでなければならない。

1. この変更を入れる前に3つの欄に保存されていた文章を、アプリは、この変更を入れたあとも1文字も変えずに持ち続ける。利用者がその職務経歴書を開いたら、アプリは、今までと同じ文章を表示する。
