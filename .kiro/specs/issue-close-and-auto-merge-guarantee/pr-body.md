# PR 本文に入れる文面

## 所有者に承認してほしい変更(ゲート設定)

この PR は、機能そのものがゲート設定の領域にあるため、ゲート設定の変更を含みます。

- ワークフローの追加: `auto-merge.yaml`(自動マージの予約と付け直し)、`close-linked-issues.yaml`(マージ後の Issue のクローズ)
- ワークフローの削除: `rearm-auto-merge.yaml`(`auto-merge.yaml` が置き換える)
- 既存の必須チェック `escape-hatch`(`guardrails.yaml`)に、新しいスクリプトのテスト3本を追加。必須チェックは新しく足していません(`required-checks.json` は変更なし)
- 出荷手順(`.claude/skills/ship/SKILL.md`)の変更: AI は自動マージの予約の操作をせず、仕組みが予約したことを確かめる形にしました

理由: PR のマージ後に Issue が開いたまま残ること(#448)と、自動マージの予約が AI の手順に依存していることを、仕組みの側で解消するためです。

## この PR 自身についての注意

- この PR では、今の付け直しのワークフローは削除済みで、新しい仕組みもまだ働きません。**承認のあとに自動マージの予約が外れたら、手で予約し直してください**(PR の画面の「Enable auto-merge」)。
- 新しい `Auto Merge` のワークフローの実行が、この PR では赤になることがあります。main にまだスクリプトが無いためで、必須チェックではありません。マージの妨げにはなりません。

## マージ後に所有者が行うこと

導入のときに1回だけ行う作業です。

1. Actions の画面で「Auto Merge」を手動で1回実行する(Run workflow。ブランチは main)。緑で終わることを確かめる。
2. Actions の画面で「Close Linked Issues」を手動で1回実行する(同じく main)。緑で終わることを確かめる。直近7日にマージされた PR のうち、閉じ漏れていた Issue があれば、ここで閉じます。`Refs:` にしか書かれていない開いた Issue があれば、知らせのコメントが付きます(いまのところ、どちらも該当は無い見込みです)。

## 導入後の確認(所有者)

次の8項目を確かめてください。うまくいかない項目があれば、Claude Code に調査を依頼してください。

1. 所有者のアカウントで PR を作る。1〜2分のうちに、自動マージの予約が付く。
2. その PR の予約を手で外す。1〜2分のうちに、予約が付け直される。
3. 仕組みが予約した PR がマージされたあと、Actions で `dependency-graph.yaml` と `update-pr-branches.yaml` の実行が起動している。
4. `pre-merge-check` ラベルを付けた PR が、所有者が承認するまでマージされない。
5. 本文に `Refs: #<番号>` だけを書き、`Closes` を書かない検証用の PR をマージする。その Issue に知らせのコメントが付き、所有者に通知が届く。
6. 本文に `Closes #<番号>` を書いた PR をマージする。その Issue が閉じている。
7. 5 の知らせが付いたあと、**マージから5分以上たってから**「Close Linked Issues」を手動でもう一度実行する。知らせのコメントが増えていない。
8. 1 の PR が開いている間に「Auto Merge」を手動で実行する。緑で終わり、実行のログに、開いている PR ごとの結果の行(`pr=<番号> result=...`)が出ている。1 の PR の行は `result=already`(予約済み)になる。
   - 見直しだけで予約が付くこと(イベントを取りこぼした場合)は、手では再現できません。予約を外すと、外したことを起点にすぐ付け直されるためです。この動きはスクリプトの自動テストで確かめています。

5 と 6 の検証用の PR と Issue は、確認のあとで閉じてかまいません。
