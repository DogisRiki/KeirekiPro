# 要件

## 元の要望
Issue #473: spec無しのPRがIssue本文の「決めた方式」から外れたらマージされないようにする

### きっかけ

spec の要否の判断についての壁打ちの調査中にAIが見つけ、所有者が別の要望として起票すると決めた。

### 困っていること

- spec 無しで実装したPRが、Issue本文の「決めた方式」と違う作りになっていても、今の自動レビューは止めない(AIの提案を了承)

### どうなれば解決か

- spec 無しのPRが Issue本文の「決めた方式」と違う作りなら、自動レビューが指摘し、直るまでマージされない(AIの提案を了承)

## はじめに

所有者は、Issue本文の「決めた方式」の見出しに、所有者が決めて変えてはいけない作り方だけを書く。spec 無しで進めるPRでは、自動レビュー(codex-review)が、PR本文の `Refs:` が指すIssueの本文を判定の基準にする。ところが、今の自動レビューは、Issueの記述と違う作りでも、PR本文に理由が書いてあれば適合と判定する。そのため、Claude が「決めた方式」と違う作りにして理由を書けば、PRはそのままマージされてしまう。

この spec は、自動レビューが「決めた方式」から外れた作りを指摘し、直るまでマージされないようにする。

## 範囲

- この spec で決めること: 自動レビューがIssue本文を判定の基準にするPRのうち、そのIssueの本文に「決めた方式」の見出しがあるPRの判定
- この spec で決めないこと: 自動レビューを止めている今の状態を再開するかどうか(所有者が決める。この spec は自動レビューを再開しない)。PR本文に `Spec:` を書いて spec を判定の基準にするPRの判定。Issue本文の「決めた方式」の書き方(起票の決まりのまま)。自動レビューの往復の上限と、上限に達したときの扱い。「決めた方式」どおりに作れないと分かったときの Claude の動き(今の `/start` の決まりのまま)
- この spec が前提にしていること: 所有者が自動レビューを止めている間(リポジトリの変数 `CODEX_REVIEW_ENABLED` が `true` でない間)は、自動レビューが動かないので、この spec が足す判定も動かない。所有者が自動レビューを再開すると、この spec が足す判定も動く。分けた部分のIssueのPRでは、`Refs:` が分けた部分のIssueを指すので、自動レビューは分けた部分のIssueの本文を判定の基準にする。自動レビューの設定は所有者の承認が要るファイルにあるので、この spec のPRは所有者の承認がないとマージされない

## 要件

### 要件1 自動レビューが「決めた方式」から外れた作りを止める

「決めた方式」は、所有者が決めて変えてはいけない作り方である。Claude が理由を添えて別の作り方にしても、所有者が決めたことが守られないのは変わらない。そこで、所有者は、「決めた方式」から外れたPRを、理由の有無に関わらず、直るまでマージさせたくない。

1. 自動レビューがIssue本文を判定の基準にするPRで、そのIssueの本文に「決めた方式」の見出しがあるときは、自動レビューは、PRの変更が「決めた方式」の各項目に沿っているかを確かめる。
2. 自動レビューは、PRの変更が「決めた方式」の項目のどれか1つにでも「沿っていない」と判定したときは、spec適合の判定を「直す必要あり」(`CHANGES_REQUESTED`)にする。自動レビューがこの判定を出したPRは、今の自動レビューと同じく、判定が「問題なし」(`LGTM`)になるまでマージされない。
3. PR本文に「決めた方式」と違う作りにした理由が書いてあっても、自動レビューは、「決めた方式」から外れたPRの判定を「直す必要あり」のままにする。
4. 「決めた方式」の項目の末尾に「(AIの提案を了承)」の印があっても、自動レビューは、その項目を、印の無い項目と同じく確かめる。所有者は、その項目を了承した時点で、その項目を自分の決めたこととして扱うからである。
5. 自動レビューは、「決めた方式」から外れたと指摘するときに、外れた項目の文面と、外れている変更のファイルと行と、その項目に沿わせる直し方を、PRのレビューのコメントに書く。
6. 自動レビューは、「決めた方式」から外れたかどうかの判定の結果を、spec適合の評価の中で、「決めた方式」の項目ごとに「沿っている」「沿っていない」「このPRの変更からは判定できない」のどれかで示す。
7. 「決めた方式」の項目が、作業の順番や所有者の操作のように、PRの変更からは沿っているかどうかを判定できないことを書いているときは、自動レビューは、その項目を「このPRの変更からは判定できない」と示す。自動レビューは、「このPRの変更からは判定できない」項目だけを理由に、spec適合の判定を「直す必要あり」にしない。Claude がPRを直しても、その項目の判定は変わらないからである。

### 要件2 「決めた方式」に当たらないPRの判定は今のまま変えない

所有者が止めたいのは、所有者が決めた作り方から外れることだけである。自動レビューが、所有者が決めていない作り方まで厳しく判定すると、Claude が理由を添えて選んだ妥当な作り方まで止まり、自動レビューの往復が増える。そこで、所有者は、「決めた方式」に当たらない判定を今のまま残したい。

1. Issue本文に「決めた方式」の見出しが無いときは、自動レビューは、今と同じ基準でPRを判定する。
2. 「決めた方式」に書かれていない作り方がIssueの記述と違うときは、自動レビューは、今と同じく、PR本文に理由が書いてあれば適合と判定する。
3. PR本文に `Spec:` を書いて spec を判定の基準にするPRは、自動レビューは、今と同じ基準で判定する。
