# 要件

## 元の要望
Issue #604: メールアドレスの持ち主であることを確かめてから、アカウントのメールアドレスとして扱う

### きっかけ

所有者が、メールアドレスの扱いを、ほかの改善より先に行うと決めた。

### やりたいこと

- 利用者がメールアドレスとパスワードで登録したとき、アプリは、そのメールアドレスに確認のメールを送る。アプリは、利用者がメールの中の確認の操作を済ませてから、そのメールアドレスをアカウントのメールアドレスとして扱う。(AIの提案を了承)
- 利用者があとからアカウントにメールアドレスを設定するときも、アプリは同じ確認を行う。(AIの提案を了承)

### どうなれば解決か

- 確認の操作を済ませていないメールアドレスは、どの機能でも、アカウントのメールアドレスとして扱われない。(AIの提案を了承)
- すでにあるアカウントのメールアドレスも、利用者が確認の操作を済ませるまでは、同じように扱われる。(AIの提案を了承)

### やらないこと

- Issue、PR の本文、コミットのメッセージには、新しい動きだけを書く。今の動きから変える理由は書かない。

## はじめに

アプリは、利用者がメールアドレスの持ち主であることを確かめてから、そのメールアドレスをアカウントのメールアドレスとして扱う。アプリは、確かめるために、そのメールアドレスに確認のメールを送る。利用者は、メールの中の確認のリンクを押して、確認を済ませる。

この spec では、アプリが確認のメールを送る場面と、確認前の利用者が見る画面と、確認前のメールアドレスを各機能がどう扱うかを決める。所有者は、次の5つを決めた。

- 利用者が確認を済ませるために何をするか
- アプリが、確認のリンクをいつまで使えるようにするか
- アプリが確認のメールを送り直すまでに、どれだけ間を空けるか
- アプリが、Google と GitHub が返したメールアドレスをどう扱うか
- 利用者が確認前のメールアドレスでパスワードの再設定を求めたときに、アプリがどう動くか

この文書では、言葉を次の意味で使う。

- 確認のメール: アプリが、メールアドレスの持ち主であることを確かめるために送るメール。確認のリンクが入っている
- 確認を済ませる: 利用者が、確認のメールの中の確認のリンクを押し、アプリがそのリンクを受け付けること
- 確認前の登録: 利用者がメールアドレスとパスワードで登録したが、まだ確認を済ませていない登録。確認前の登録は、アカウントではない
- 前からあるアカウント: この spec の変更を本番に入れる前から本番にあるアカウント
- 確認前のメールアドレス: アカウントが持っているが、まだ確認を済ませていないメールアドレス。この spec の変更のあとは、前からあるアカウントだけが確認前のメールアドレスを持つ
- 設定待ちのメールアドレス: 利用者があとからアカウントに設定しようとしたが、まだ確認を済ませていないメールアドレス。設定待ちのメールアドレスは、アカウントのメールアドレスではない

## 範囲

- この spec で決めること: この spec では、次の6つを決める。
  - メールアドレスとパスワードで登録したときと、あとからメールアドレスを設定したときに、アプリが確認のメールを送ること
  - アプリが、確認のリンクをいつまで使えるようにするかと、確認のメールをどう送り直すか
  - 確認を済ませていない利用者を、アプリがログインさせるかどうか
  - 前からあるアカウントのメールアドレスを、アプリがどう扱うか
  - 利用者が Google と GitHub でログインしたときに、アプリがメールアドレスをどう扱うか
  - 退会完了のお知らせのメール、2段階認証、外部連携の解除、パスワードの再設定の各機能が、確認前のメールアドレスをどう扱うか
- この spec で決めないこと: この spec では、次の4つを決めない。
  - 利用者が、確認を済ませたメールアドレスを、別のメールアドレスに変えること。今も、アプリは、利用者にアカウントのメールアドレスを変えさせない
  - アプリが、メールアドレスの大文字と小文字を同じものとみなすかどうか
  - 管理者が利用者にメールやお知らせを送る機能。この機能は #444 で扱う
  - アプリが送るメールの送り元をどう設定するかと、メールを送る外部の仕組みをどう設定するか
- この spec が前提にしていること: この spec は、次の2つを前提にする。
  - アプリは、今と同じく、本番で利用者のメールアドレスにメールを送れる
  - Google と GitHub は、メールアドレスを返すときに、そのメールアドレスの持ち主を自分の側で確かめたかどうかを返す

## 要件

### 要件1 登録したメールアドレスの確認を済ませてから、アカウントを作る

所有者は、利用者がメールアドレスの持ち主であることをアプリが確かめてから、アプリがそのメールアドレスをアカウントのメールアドレスとして扱うことを望んでいる。そこで、アプリは、利用者が確認を済ませたときに、はじめてアカウントを作る。アプリは、確認を済ませた登録だけからアカウントを作る。そのため、同じメールアドレスで先に登録した人がいても、メールアドレスの持ち主は、確認を済ませてアカウントを作れる。打ち間違えたメールアドレスで登録した人も、正しいメールアドレスで登録し直せる。

1. 利用者がメールアドレスとパスワードで登録したら、アプリは、そのメールアドレスに確認のメールを送る。アプリは、この時点ではアカウントを作らない。アプリは、確認のメールを送ったことと、メールの中の確認のリンクを押すよう案内する文を、画面に出す。
2. 利用者が確認前の登録の確認を済ませたら、アプリは、その登録のメールアドレスとパスワードとユーザー名でアカウントを作る。アプリは、そのメールアドレスを、確認を済ませたアカウントのメールアドレスとして扱う。アプリは、登録が済んだことを画面に出し、利用者がログインの画面へ進めるようにする。
3. アカウントを作ったら、アプリは、登録完了のお知らせのメールを、そのアカウントのメールアドレスに送る。
4. 同じメールアドレスの確認前の登録があっても、アプリは、別の登録を受け付ける。同じメールアドレスの確認前の登録が2つ以上あるときは、アプリは、先に確認を済ませた登録だけからアカウントを作る。
5. 利用者が確認のリンクを押したときに、その登録のメールアドレスをすでにアカウントが持っていたら、アプリはアカウントを作らない。アプリは、このメールアドレスでは登録できないことを画面に出す。
6. アプリが確認前の登録のために最後に送った確認のリンクの期限が切れたら、アプリは、その確認前の登録を消す。アプリは、確認のメールを送らずに受け付けた確認前の登録を、受け付けてから24時間たったときに消す。ただし、そのあとにアプリがその登録のために確認のメールを送ったときは、アプリは、受け付けてから24時間たってもその登録を消さず、最後に送った確認のリンクの期限が切れたときに消す。
7. 利用者が登録しようとしたメールアドレスをすでにアカウントが持っていたら、アプリは、今と同じく登録を断る。

### 要件2 確認のリンクの期限と、確認のメールの送り直し

確認のリンクがいつまでも使えると、メールが他人の目に触れたときに、その人が確認を済ませられてしまう。一方で、確認のリンクの期限が切れたあとに利用者が確認のメールを受け取り直せないと、その利用者はアプリを使えないままになる。他人が送り直しを何度も求めると、メールアドレスの持ち主に大量のメールが届く。そこで、アプリは、確認のリンクを決まった時間だけ使えるようにし、同じメールアドレスへ確認のメールを送り直す間隔を空ける。

1. 確認のリンクは、アプリがその確認のメールを送ってから24時間使える。ただし、利用者がパスワードの再設定を求めたときにアプリが送る確認のメールのリンクは、アプリがそのメールを送ってから10分だけ使える。このリンクを押した人は、確認に続けてパスワードを再設定できる。そのため、アプリは、このリンクを、今のパスワードの再設定のリンクと同じ10分で使えなくする。
2. 確認のリンクは1回だけ使える。
3. アプリが、同じ確認前の登録か同じアカウントのために新しい確認のメールを送ったら、それより前にその登録かそのアカウントのために送った確認のリンクは使えなくなる。
4. 利用者が、期限が切れたリンクか、アプリが新しい確認のメールを送ったために使えなくなったリンクを押したら、アプリは、そのリンクが使えないことと、確認のメールを送り直すボタンを画面に出す。利用者がボタンを押したら、アプリは、そのリンクを送ったメールアドレスに、そのリンクと同じ確認のための新しい確認のメールを送る。利用者が押したリンクが、利用者がパスワードの再設定を求めたときにアプリが送った確認のメールのリンクだったとする。そのときは、アプリが送り直す確認のメールのリンクも、アプリがそのメールを送ってから10分だけ使える。利用者がそのリンクを押すと、アプリは、続けてパスワードの再設定の画面を出す。パスワードを忘れた利用者が、もう一度パスワードの再設定を求め直さずに済むようにするためである。そのリンクの確認前の登録をアプリがすでに消していたときは、アプリは、ボタンの代わりに、もう一度登録するよう案内する文を画面に出す。
5. 利用者が、確認を済ませたあとのリンクをもう一度押したら、アプリは、確認がすでに済んでいることを画面に出す。
6. アプリは、同じメールアドレスへの確認のメールを、1分に1回まで送る。前の確認のメールを送ってから1分たつ前に利用者が送り直しを求めたら、アプリは、確認のメールを送らずに、少し待ってから求め直すよう案内する文を画面に出す。
7. 利用者がメールアドレスとパスワードで登録したときに、アプリがそのメールアドレスへ前の確認のメールを送ってから、まだ1分たっていないとする。そのとき、アプリは、登録を受け付け、確認のメールを送らない。このとき、アプリは、少し待ってから求め直すよう案内する文ではなく、登録したときにいつも出す文を画面に出す。他人に、そのメールアドレスへ直前に確認のメールが送られたことを知られないようにするためである。登録した利用者は、1分たったあとに、ログインの画面から確認のメールを送り直せる。

### 要件3 確認前の登録をした利用者と、確認前のメールアドレスを持つアカウントの利用者は、メールアドレスとパスワードでログインできない

アプリは、メールアドレスをログインに使っている。そのため、アプリが、確認前の登録をした利用者か、確認前のメールアドレスを持つアカウントの利用者をログインさせると、アプリは、確認を済ませていないメールアドレスをアカウントのメールアドレスとして扱うことになる。そこで、アプリは、確認前の登録をした利用者と、確認前のメールアドレスを持つアカウントの利用者を、メールアドレスとパスワードでログインさせない。前からあるアカウントの利用者は、次のログインのときに、ログインの画面から確認のメールを受け取れる。

1. 確認前の登録のメールアドレスとパスワードが正しく入力されたら、アプリは、入力した利用者をログインさせない。アプリは、確認がまだであることと、確認のメールを送り直すボタンを画面に出す。
2. 前からあるアカウントの確認前のメールアドレスとパスワードが正しく入力されたときも、アプリは、入力した利用者をログインさせない。アプリは、確認がまだであることと、確認のメールを送るボタンを画面に出す。利用者がボタンを押したら、アプリは、そのメールアドレスに確認のメールを送る。
3. パスワードが違うときは、確認前の登録でも確認前のメールアドレスでも、アプリは今と同じ文を画面に出す。アプリは、確認がまだであることを画面に出さない。パスワードを知らない人に、そのメールアドレスが登録されているかどうかを知られないようにするためである。
4. 前からあるアカウントの利用者が確認を済ませたら、アプリは、そのメールアドレスを確認を済ませたアカウントのメールアドレスとして扱い、利用者がログインの画面へ進めるようにする。そのあとのログインと2段階認証は、今と同じに動く。
5. 設定待ちのメールアドレスとパスワードが入力されたら、アプリは、そのメールアドレスのアカウントが無いときと同じく、今と同じ文を画面に出し、入力した利用者をログインさせない。設定待ちのメールアドレスは、アカウントのメールアドレスではないためである。設定待ちのメールアドレスを持つ利用者は、今と同じく Google か GitHub でログインし、ユーザー設定の画面から確認のメールを受け取れる。

### 要件4 あとから設定するメールアドレスも、確認を済ませてからアカウントに付ける

所有者は、Issue の本文で、利用者があとからアカウントにメールアドレスを設定するときも、アプリが同じ確認を行うと決めた。あとから設定したメールアドレスを確認せずにアカウントに付けると、アプリは、持ち主を確かめていないメールアドレスをアカウントのメールアドレスとして扱うことになる。今は、メールアドレスを持たないアカウントの利用者が、メールアドレスとパスワードを設定する画面で、メールアドレスを設定できる。

1. 利用者がメールアドレスとパスワードを設定する画面でメールアドレスを設定したら、アプリは、そのメールアドレスに確認のメールを送り、そのメールアドレスを設定待ちのメールアドレスにする。アプリは、確認を済ませるまで、設定待ちのメールアドレスをアカウントのメールアドレスとして扱わない。同じ画面で設定したパスワードは、アプリが今と同じくその時点でアカウントに設定する。
2. 利用者が設定待ちのメールアドレスの確認を済ませたら、アプリは、そのメールアドレスを、確認を済ませたアカウントのメールアドレスにする。
3. 確認を済ませる前に、利用者が別のメールアドレスを設定し直したら、アプリは、設定待ちのメールアドレスを新しいメールアドレスに置き換え、新しいメールアドレスに確認のメールを送る。アカウントがすでにパスワードを持つときは、アプリは、利用者が今のパスワードを正しく入れたときだけ、設定し直しを受け付ける。今のパスワードを忘れた利用者は、設定待ちのメールアドレスを置き換えられない。その利用者も、今と同じく Google か GitHub でログインできる。
4. 利用者が設定しようとしたメールアドレスをすでにアカウントが持っていたら、アプリは設定を断り、このメールアドレスは使えないことを画面に出す。
5. 利用者が確認のリンクを押したときに、そのメールアドレスをすでにほかのアカウントが持っていたら、アプリは、そのメールアドレスをアカウントに付けない。アプリは、このメールアドレスは使えないことを画面に出す。
6. 利用者がメールアドレスを設定したときか設定し直したときに、アプリがそのメールアドレスへ前の確認のメールを送ってから、まだ1分たっていないとする。そのとき、アプリは、そのメールアドレスを設定待ちのメールアドレスにし、確認のメールを送らない。このとき、アプリは、少し待ってから求め直すよう案内する文ではなく、メールアドレスを設定したときにいつも出す文を画面に出す。他人に、そのメールアドレスへ直前に確認のメールが送られたことを知られないようにするためである。利用者は、1分たったあとに、ユーザー設定の画面から確認のメールを送れる。

### 要件5 前からあるアカウントのメールアドレスは、確認前として扱う

所有者は、Issue の本文で、前からあるアカウントのメールアドレスも、利用者が確認を済ませるまでは、確認前のメールアドレスと同じように扱うと決めた。前からあるアカウントには、利用者の職務経歴書が保存されている。そのため、アプリが確認前のメールアドレスを持つアカウントを消すと、利用者は職務経歴書を失う。

1. この spec の変更を本番に入れた時点で、アプリは、前からあるアカウントが持っているメールアドレスを、すべて確認前のメールアドレスとして扱う。
2. アプリは、確認前のメールアドレスを持つアカウントを消さない。アプリは、そのアカウントの職務経歴書も消さない。

### 要件6 確認前のメールアドレスと設定待ちのメールアドレスを、ユーザー設定の画面に確認待ちとして見せる

利用者は、自分のメールアドレスの確認が済んでいるかどうかを、ログインしたあとにも知りたい。Google や GitHub だけでログインしている利用者は、ログインの画面から確認のメールを受け取る機会が無い。

1. アカウントが確認前のメールアドレスか設定待ちのメールアドレスを持っていたら、アプリは、ユーザー設定の画面で、そのメールアドレスを確認待ちとして見せる。
2. アプリは、ユーザー設定の画面に、確認のメールを送るボタンを出す。利用者がボタンを押したら、アプリは、確認前のメールアドレスか設定待ちのメールアドレスに、確認のメールを送る。

### 要件7 Google と GitHub が確かめたメールアドレスは、確認を済ませたものとして扱う

Google と GitHub は、自分の側でメールアドレスの持ち主を確かめている。そこで、アプリは、Google や GitHub だけでログインしている利用者のメールアドレスを、利用者がアプリの確認のメールを受け取らなくても、確認を済ませたものとして扱えるようにする。

1. 利用者が Google か GitHub でログインしたときに、その利用者の Google か GitHub が結び付いたアカウントがあるとする。そのとき、アプリは、今と同じく、その利用者をそのアカウントにログインさせる。アプリは、今と同じく、Google か GitHub が返したメールアドレスを、そのアカウントに付けない。
2. 利用者が、自分のアカウントに結び付いた Google か GitHub でログインしたとする。そのとき、アプリは、Google か GitHub が持ち主を確かめたものとして返したメールアドレスが、そのアカウントの確認前のメールアドレスか設定待ちのメールアドレスと同じなら、そのメールアドレスを、確認を済ませたアカウントのメールアドレスにする。利用者は、確認のメールのリンクを押さなくて済む。ただし、設定待ちのメールアドレスをすでにほかのアカウントが持っていたら、アプリは、利用者が確認のリンクを押したときと同じく、そのメールアドレスをアカウントに付けず、設定待ちのメールアドレスのまま残す。アプリがそのメールアドレスをアカウントに付けたときも、付けずに設定待ちのメールアドレスのまま残したときも、アプリは、今と同じくその利用者をログインさせる。
3. 利用者の Google か GitHub が結び付いたアカウントが無く、アプリが今と同じく新しいアカウントを作るとする。そのとき、Google か GitHub が持ち主を確かめたと返したメールアドレスがあれば、アプリは、そのメールアドレスを、確認を済ませたアカウントのメールアドレスとして新しいアカウントに付ける。アプリは、そのメールアドレスに確認のメールを送らない。
4. Google か GitHub が持ち主を確かめたと返さなかったメールアドレスは、アプリが受け取らない。アプリが新しいアカウントを作るときは、アプリは、今の Google での扱いと同じく、メールアドレスを持たないアカウントを作り、その利用者をログインさせる。
5. Google か GitHub が持ち主を確かめたと返したメールアドレスと同じメールアドレスの確認前の登録があっても、アプリは、今と同じく、Google か GitHub でログインした利用者のアカウントを作り、その利用者をログインさせる。

### 要件8 確認前のメールアドレスのアカウントには、Google と GitHub のログインを結び付けない

アプリは、Google か GitHub でログインした利用者を同じメールアドレスのアカウントに結び付けるときに、そのメールアドレスの確認が済んでいることを条件にする。そうすると、アプリは、メールアドレスの持ち主であることを確かめたアカウントにだけ、Google か GitHub を結び付ける。

1. 利用者が Google か GitHub でログインしたときに、その利用者の Google か GitHub が、アプリのどのアカウントにもまだ結び付いていないとする。そのとき、Google か GitHub が返したメールアドレスと同じ確認前のメールアドレスを持つアカウントがあれば、アプリは、そのアカウントに、その Google か GitHub を結び付けない。アプリは、その利用者をログインさせない。
2. このとき、アプリは、そのメールアドレスのアカウントがあることと、メールアドレスとパスワードでログインして先に確認を済ませるよう案内する文を、画面に出す。
3. そのアカウントのメールアドレスが確認を済ませたものになったあとは、アプリは、今と同じく、Google か GitHub をそのアカウントに結び付ける。

### 要件9 確認前のメールアドレスでパスワードの再設定を求めたら、確認とパスワードの再設定を続けて行う

確認前のメールアドレスを持つアカウントの利用者は、メールアドレスとパスワードでログインできない。そのため、その利用者がパスワードを忘れると、その利用者は、ログインの画面から確認のメールを受け取れない。そこで、アプリは、パスワードの再設定を求めた利用者に、確認のメールを送り、確認とパスワードの再設定を1通のメールで済ませられるようにする。

1. 利用者が確認前のメールアドレスでパスワードの再設定を求めたら、アプリは、パスワードの再設定のメールの代わりに、そのメールアドレスに確認のメールを送る。
2. 利用者がその確認のメールか、アプリが送り直したその確認のメールの中の確認のリンクを押し、アプリがそのリンクを受け付けたら、アプリは、続けてパスワードの再設定の画面を出す。利用者がパスワードを再設定したら、アプリは、そのあと今と同じくパスワードの再設定を済ませる。
3. 利用者が、確認前の登録のメールアドレスか設定待ちのメールアドレスでパスワードの再設定を求めたときは、アプリはメールを送らない。確認前の登録はアカウントではなく、設定待ちのメールアドレスはアカウントのメールアドレスではないためである。
4. 利用者がパスワードの再設定を求めたら、アプリは、次の4つのどのときも、画面に同じ文を出す。4つは次のとおりである。
   - 入力されたメールアドレスが、アカウントの確認を済ませたメールアドレスであるとき
   - 入力されたメールアドレスが、アカウントの確認前のメールアドレスであるとき
   - 入力されたメールアドレスが、確認前の登録のメールアドレスか設定待ちのメールアドレスであるとき
   - 入力されたメールアドレスのアカウントが無いとき

   アプリが同じ文を出すのは、他人に、そのメールアドレスのアカウントがあるかどうかと、確認が済んでいるかどうかを知られないようにするためである。
5. 利用者が確認前のメールアドレスでパスワードの再設定を求めたときに、アプリがそのメールアドレスへ前の確認のメールを送ってから、まだ1分たっていないとする。そのとき、アプリは確認のメールを送らない。このときも、アプリは、少し待ってから求め直すよう案内する文ではなく、パスワードの再設定を求めたあとにいつも出す文と同じ文を画面に出す。

### 要件10 確認前のメールアドレスと設定待ちのメールアドレスを、ほかの機能でも使わない

所有者は、確認を済ませていないメールアドレスを、どの機能でもアカウントのメールアドレスとして扱わないと決めた。この要件では、ここまでの要件で決めていない機能での扱いを決める。

1. アプリは、確認前のメールアドレスと設定待ちのメールアドレスに、確認のメールのほかのメールを送らない。たとえば、確認前のメールアドレスを持つアカウントの利用者が退会しても、アプリは退会完了のお知らせのメールを送らない。アプリは、前からあるアカウントの利用者に、この spec の変更を前もって知らせるメールも送らない。
2. アプリは、2段階認証を有効にできるかを判断するときに、確認前のメールアドレスと設定待ちのメールアドレスを、メールアドレスが無いものとして扱う。今は、アプリは、メールアドレスとパスワードの両方を持つアカウントにだけ、2段階認証を有効にさせている。
3. アプリは、外部連携を解除できるかを判断するときに、確認前のメールアドレスと設定待ちのメールアドレスを、メールアドレスが無いものとして扱う。今は、アプリは、メールアドレスとパスワードを持たず外部連携が1つしかないアカウントには、外部連携を解除させない。
