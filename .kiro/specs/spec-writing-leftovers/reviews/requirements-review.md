### 申告

**1. どれかの spec の書き換えを止めたら、この spec の変更をすべて出荷しない** — 要件4の項目5

- Issue の記載: なし(「上の5つを、1つの Issue でまとめて直す」とあるが、書き換えが途中で止まったときに、残りの修正を出荷するかどうかは書かれていない)
- 決めたこと: どれか1つの spec でも書き換えを止めたら、Claude は、確かめ済みの spec の書き換えも、困っていること1〜4 の修正(雛形の言い回し、タスクの決まりの見出し、`ready_for_implementation`)も出荷せず、所有者がどう進めるかを決めるまで待つ
- 他にありえた選択肢: 困っていること1〜4 の修正と、確かめ済みの spec の書き換え(spec.json に `spec_format: 2` を書いて)だけを先に出荷し、止めた spec と印の削除を所有者の判断の後に回す。または、止めた spec だけを所有者に見せ、所有者が決めるまで作業を止めずに残りの spec の書き換えを続ける
- 外れていた場合: 1つの spec で止まると、Issue の5つの問題のうち、書き換えと関係の無いもの(雛形の言い回し、タスクの決まりの見出し、`ready_for_implementation`)も所有者の判断まで直らない。逆に分けて出荷すると、印を見分ける道具が残ったまま印付きの新しい書き方の spec が main に入り、要件4の項目1で印を消す工程が2回目のPRに分かれる

**2. サブエージェントが比べるのは「spec が決めたこと」であり、書き方の違いは食い違いとしない** — 要件2の項目2

- Issue の記載: あり(「書き換えの前と後で中身が同じかだけを確かめる」)。ただし「中身」が何かは書かれていない
- 決めたこと: 比べる中身は spec が決めたこと(要件と項目、設計で決めたこと、タスクとその完了の状態、番号)とし、`spec-writing.md` が求める書き方の違い(見出しと目印の名前、節の並び、文の形、利用者の立場を名乗る行を書き直した理由の段落)は食い違いとして扱わない
- 他にありえた選択肢: 書き換え前の本文に無い文はすべて食い違いとして返させ、理由の段落も書き換え前の Objective の行の中身に限る。または、所有者が Issue で「ほかの観点では一切確かめない」と言った以上、比べる中身の定義も所有者に確かめてから決める
- 外れていた場合: 所有者が「中身」を本文の文章そのものと考えていた場合、理由の段落のように新しく起こした文が確かめの対象から外れ、所有者の想定より緩い確かめで承認済みの記録が付く
