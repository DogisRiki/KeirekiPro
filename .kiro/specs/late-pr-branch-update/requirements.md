# 要件

## 元の要望
Issue #511: 最後に main に push されたあとに出したPRが、out-of-date のまま止まる

### きっかけ

#491 の出荷(PR #509)で、PRが「This branch is out-of-date with the base branch」のまま止まり、所有者が気づいて起票を指示。

### 困っていること

- main に最後に push されたあとに、それより前の main から作ったブランチでPRを出すと、ブランチが main の最新に合わせられず、out-of-date のままマージが進まない。
- 所有者が気づいて声をかけるまで、PRが止まったままになる。

### どうなれば解決か

- main に最後に push されたあとに出したPRも、人が手でブランチを更新しなくても、main の最新に合わせられてマージまで進む。(AIの提案を了承)

## はじめに

このリポジトリでは、GitHub は、PRのブランチが main の最新を含んでいないと、そのPRを main にマージさせない。そのため、main が進むと、開いているPRは、ブランチを main の最新に合わせるまで main にマージされない。今は、main に push されたときにワークフローが起動し、その時点で開いているPRのブランチを main の最新に合わせている。

ところが、ワークフローが起動するのは main に push されたときだけである。main に push されたあとに、それより前の main から作ったブランチでPRを出すと、ワークフローはそのPRのブランチを合わせない。次に main に push されるまで、そのPRはマージされないまま止まる。#509 では、#508 が main に入った6分後にPRが出され、所有者が気づいて声をかけるまで止まっていた。

この spec は、PRを出した時点でブランチが main より古くても、人の操作なしに main の最新に合わせられ、マージまで進むようにする。

## 範囲

- この spec で決めること: PRを出したときにブランチを main の最新に合わせること、ワークフローがブランチを合わせられなかったPRの扱い、`/ship` で出したPRがマージされるまで Claude が見届けること
- この spec で決めないこと: main に push されたときにワークフローがブランチを合わせる今の動き(対象のPRも、衝突したときの扱いも変えない)、PRのブランチが main の最新を含んでいないとマージさせない設定を変えること、マージ列(merge queue)への切り替え、所有者への知らせを足すこと
- この spec が前提にしていること: ブランチを main の最新に合わせると、必須の検査が合わせたあとのブランチで改めて動く。今のワークフローは、この前提を満たすためにボットのトークンでブランチを合わせている

## 要件

### 要件1 PRを出したときにブランチを main の最新に合わせる

所有者は、PRを出したのが main への push の前か後かによらず、人が手でブランチを更新しなくてもPRがマージまで進んでほしい。今は、main への push のあとに出したPRが、次の push まで止まり、所有者が気づくまで誰も動かないからである。

1. main に向けたPRが出されたときに、PRのブランチが main の最新を含んでいなければ、ワークフローは、次に main に push されるのを待たずに、人の操作なしでPRのブランチを main の最新に合わせる。
2. 所有者か Claude が下書きのPRを下書きでなくしたとき、または閉じたPRを開き直したときも、ワークフローは、PRが出されたときと同じくPRのブランチを main の最新に合わせる。
3. PRが出されたときにワークフローが合わせる対象のPRは、main に push されたときにワークフローが合わせる対象のPRと同じである。今の対象は、同じリポジトリのブランチから出されたPRのうち、下書きでもカナリアPRでもないものである。
4. PRのブランチがすでに main の最新を含んでいれば、ワークフローはPRのブランチを変えない。
5. ワークフローがPRのブランチを main の最新に合わせたら、必須の検査が合わせたあとのブランチで改めて動く。検査がすべて通り、必要な承認が揃えば、PRは人の操作なしにマージされる。

### 要件2 ブランチを合わせられなかったPRは、出した Claude が直す

所有者は、PRが止まったことを知らされても、Claude にそのPRを直すよう頼むことしかできない。そのため、所有者は、ワークフローがブランチを合わせられなかったPRを、知らせを待たずに Claude が直してほしい。

1. main に push されたときに、PRの変更と main の変更が衝突してワークフローがPRのブランチを合わせられなかったら、ワークフローは、どのPRを合わせられなかったかと、その理由を実行ログに残す。ワークフローは、所有者に知らせを送らない。PRを出した時点ですでに衝突しているPRでは、GitHub がワークフローを起動しないので、PRを出したときのワークフローは動かない。
2. `/ship` で出したPRについて、必須の検査の結果がすべて出たあとに、PRのブランチが main の最新を含んでいなければ、Claude はPRのブランチに main を取り込む。Claude は、必須の検査の結果がすべて出る前には、ブランチを合わせるための push をしない。取り込みで衝突したら、Claude は衝突を直し、品質チェックを通してから push し直す。Claude は、ワークフローが合わせられなかった理由が衝突でないときも、同じくブランチを合わせる。
3. 例外として、`/ship` で出したPRが main と衝突しているときは、Claude は必須の検査の結果を待たずに、PRのブランチに main を取り込んで衝突を直す。衝突しているPRでは、GitHub が必須の検査を起動しないので、検査の結果が出る時点が来ないからである。
4. Claude は、`/ship` で出したPRがマージされたことを確かめるまで、PRの見届けを終えない。ただし、Claude が自力では進められない次の場合は、Claude はPRがその状態であることを所有者に報告して見届けを終える。
   - PRが所有者の承認を待っているとき
   - Claude が所有者に提案して、所有者の答えを待つとき(ゲートの設定の変更や、コンテナの脆弱性の抑制の追加など)
   - 必須の検査がすべて通ったのに、自動マージの予約が付いていないとき(Claude は自分で予約を付けない)
   - 同じ失敗が3回続いたとき
