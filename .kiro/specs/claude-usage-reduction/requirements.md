# 要件

## 元の要望
Issue #566: Claude の使う量を減らし、週次制限に週の終わりまで達しないようにする

### きっかけ

> トークン使用料が多すぎるので改善したい。1週間制限がこないくらいにしたい。いつも３～４日目あたりできてしまう。

### 困っていること

- Claude の週次制限に、いつも週の3〜4日目で達してしまう。
- #526 の作業をしていたセッションで週次制限に達したあと、15ドルのクレジットを買って返事をしたら、数分で15ドルがなくなり、また週次制限に達した。

### やりたいこと

- 1つのセッションだけでなく全体を見て、Claude の使う量が跳ね上がっている主な原因を見つけ、直す。

### どうなれば解決か

- AI の判断や作業の質を落とさない直し方で、Claude の使う量が今より減っている。週次制限に週の7日目まで達しないことは、この Issue では求めない。(AIの提案を了承)
- 使う量が減っても、AI の判断や作業の質が今より落ちない。(AIの提案を了承)

### 決めた方式

- 開発に参加する人が複数いて、Windows・macOS・Linux のどれでも使う前提で直す。

### やらないこと

- 所有者や開発者が繰り返しする手作業を増やす直し方はしない。一度きりの設定はよい。

## はじめに

所有者は、Claude の週次制限に、いつも週の3〜4日目で達している。そこで、Claude は、Claude の使う量が跳ね上がっている主な原因を、AI の判断や作業の質を落とさない直し方で直し、使う量を今より減らす。

Claude は、`/start` の段階(2026-10-17)で、2026-10-03 から 2026-10-17 までの会話の記録(所有者と話す会話と、そこから呼ばれた審査役・実装役などの会話)をすべて集計した。週次制限がトークンの種類ごとにどう数えられるかは公開されていないため、Claude は、API の料金の比率(入力1、キャッシュの書き込み1.25か2、キャッシュの読み込み0.1、出力5)で重みを付けた目安で、集計した使う量を比べた。集計で分かった主な原因は次の3つである。

- 所有者と話す会話が、全体の約62%を占める。Claude は、呼び出されるたびにそれまでの会話の全体を読み直す。1つの Issue を着手から出荷まで1つの会話で進めると、会話は最大で約97万トークンまで育ち、1回の呼び出しで読み直す量の平均は約31万トークンだった。所有者と話す会話の使う量のうち、1回に40万トークンを超えて読み直した呼び出しが約54%を占める
- 所有者が会話から数時間離れて戻ると、Claude は、最初の返事のために会話の全体を書き直す。1回で約76万トークンを書き直した例が複数あった。クレジットで Claude を使っているときは、Claude が会話を書き直さずに済む時間が1時間から5分に縮むため、書き直しが続けて起きる。Claude は、#526 の作業で15ドルが数分でなくなったのは、会話の全体の書き直しが続けて起きたためと考える
- spec の実装の段階で、タスクごとに実装役と確認役が動く分が、全体の約19%を占める。審査役(Fable 5.1)は約9%である

会話をどこでどう縮めるか、または区切るかは、design で、所有者の案(spec の段階ごとに新しい会話へ切り替える)を含む候補から決める。

Claude は、design の調べ(2026-10-17)で、過去2週間の会話の記録に会話の量の上限を当てはめて試算した。会話を縮めても、会話は空に戻らず、基本の指示・CLAUDE.md・要約・スキルの手順・最近のファイルが残るので、約10万トークンから再開する。そのため、質を落とさない直し方では、使う量は全体の約2割しか減らない見込みである。週の3〜4日目で達している週次制限を7日目までもたせるには、Claude の使う量がおよそ半分に減る必要がある。所有者は、この見込みを見て、週の7日目まで達しないことを求めず、質を落とさない直し方で減らせるだけ減らすと決め、Issue の本文の「どうなれば解決か」を直した。

## 範囲

- この spec で決めること: Claude が1回の呼び出しで読み直す会話の量を抑える動き。会話を縮めたか区切ったあとも、Claude が作業を同じように続ける動き。それらが開発に参加する全員に同じく効くこと
- この spec で決めないこと: Claude の使う量を Issue ごとに集計し続け、蓄積すること。週次制限の大きさや契約のプランを変えること。PR の Codex レビューの使う量(Claude ではない)。週次制限に週の7日目まで達しないようにすること(この spec はそれを求めない)。ただし、直し方が効いたことを1回だけ確かめることは、この spec で決める。
- この spec が前提にしていること: 所有者は、週次制限をどこまで使ったかを Claude の画面で見られる

## 要件

### 要件1 質を落とさない直し方で、Claude の使う量を今より減らす

所有者は、週の3〜4日目で週次制限に達するため、残りの日は作業を止めるか、クレジットを買うことになっている。所有者は、AI の判断や作業の質を落とさないことを優先し、その範囲で Claude の使う量を減らせるだけ減らしたい。

1. Claude が、使う量が跳ね上がっている主な原因を直したあと、所有者と開発者が直す前と同じように Issue を Claude で進めたとき、Claude の使う量は直す前より少ない。
2. 所有者は、直したあとの効き目を、週次制限をどこまで使ったかを示す Claude の画面で確かめる。Claude は、効き目を確かめるための繰り返しの作業を、所有者にも開発者にも頼まない。

### 要件2 1回の呼び出しで読み直す会話の量に上限がある

集計では、使う量の大半が、長く育った会話を呼び出しのたびに読み直す分だった。会話が長くなるほど1回の呼び出しが重くなり、呼び出しの回数も増えるので、使う量は会話の長さよりも速く増える。そこで、Claude は、会話がどれだけ長く続いても、1回の呼び出しで読み直す量が一定の上限を超えないようにする。

1. Claude が1つの会話で Issue を着手から出荷まで進めても、Claude が1回の呼び出しで読み直す会話の量は、上限を超えない。上限の値は design で決める。
2. 所有者が会話から長く離れたあとに返事をしたときも、所有者がクレジットで Claude を使っているときも、Claude がその返事のために書き直す会話の量は、1回の呼び出しで読み直す量と同じ上限を超えない。
3. 上限は、所有者と話す会話にも、そこから呼ばれる審査役・実装役・確認役などの会話にも当てはまる。

### 要件3 会話を縮めたか区切ったあとも、Claude は作業を同じように続ける

会話を縮めるか区切ると、Claude は、それまでの会話の一部を読み直せなくなる。そのせいで Claude が進み具合を取り違えると、所有者が説明し直すことになるか、Claude が手順をやり直すか飛ばすことになり、作業の質が落ちる。そこで、Claude は、会話を縮めたか区切ったあとも、同じ作業を同じように続けられるようにする。

1. Claude が会話を縮めたか区切ったあとも、Claude は、次のことを所有者に尋ね直さずに続ける。
   - 進めている Issue の番号
   - 進めている spec の名前と段階
   - spec の審査が何回目の往復か、受け入れた指摘と退けた指摘
   - 実装のタスクのうち、どこまで終わったか
   - 作業のブランチと、作ったPRの番号
   - 所有者に尋ねて答えを待っている問い
2. 会話を縮めたか区切ったあとも、Claude は、終わった手順をやり直さず、まだの手順を飛ばさない。たとえば、Claude は、審査を終えた段階をもう一度審査に出さず、審査の済んでいない段階の承認を所有者に求めない。
3. 所有者が会話で伝えたことのうち、Claude がまだ作業に使っていないもの(たとえば、審査役のモデルの選び)は、会話を縮めたか区切ったあとも失われない。

### 要件4 使う量を減らしても、判断と作業の質を落とさない

所有者は、使う量を減らすために、AI の判断や作業の質が今より落ちることを望まない。Claude は、判断の質を決める、モデル・考える深さ・審査と確認の回数・判定の材料には手を付けずに、使う量を減らす。

1. Claude は、使う量を減らすために、所有者と話す会話・審査役・点検役・実装役・確認役のモデルと考える深さ(effort)を、今より下げない。
2. Claude は、使う量を減らすために、spec の審査の往復の回数の上限、実装のタスクごとの独立した確認、PR の Codex レビューを減らさない。
3. Claude は、審査役・点検役・確認役が判定に使う材料(spec の本文、変更の差分の全文など)を、短くして渡さない。
4. 所有者が承認する段階(要件・設計・タスク)と、所有者が打つコマンドは、今のまま変わらない。

### 要件5 所有者と開発者の手間を増やさず、全員に同じく効く

所有者は、使う量を減らすために、所有者や開発者が繰り返しする手作業が増えることを望まない。また、開発に参加する人は複数いて、Windows・macOS・Linux のどれでも Claude Code を使う。そこで、Claude は、直し方を、リポジトリに入れるだけで全員に同じく効くものにする。

1. Claude が、使う量が跳ね上がっている主な原因を直したあと、所有者と開発者は、Issue ごとにも spec の段階ごとにも、今はしていない操作(会話を開き直す、要約を貼り付ける、コマンドを足して打つなど)をしなくてよい。
2. Claude は、直し方をリポジトリの中に入れる。開発に参加する人は、リポジトリの最新を取り込むだけで、同じ直し方が効く。参加する人が一度だけする設定が要るときは、Claude は、その設定の手順を参加者向けの手順書に書く。
3. Claude は、Windows・macOS・Linux のどれでも効く直し方にする。また、Claude は、ターミナルの Claude Code で使う人にも、Claude Desktop で使う人にも同じく効く直し方にする。
4. Claude が会話を縮めたか区切ったことで、所有者への問いや確認は増えない。たとえば、Claude は、区切る前の会話をやめたかどうかを所有者に尋ねない。

### 要件6 直し方が実際の会話で効いたことを1回確かめる

設定やスキルを直しても、ターミナルの Claude Code と Claude Desktop で動きが違うときや、会話を縮めたあとに進み具合が残らないときは、直し方が実際には効かない。それに所有者が気づくのが、次に週次制限に達したときでは遅い。そこで、Claude は、直し方が実際の会話で効いたことを、1回だけ会話の記録で確かめる。

1. Claude は、直し方が効いた状態で始まり、会話を縮めたか区切ったことが1回以上起きた会話の記録を読み、1回の呼び出しで読み直した会話の量が上限を超えていないことを確かめる。Claude は、縮めたことも区切ったことも起きていない会話を、確かめに使わない。
2. Claude は、同じ会話の記録から、会話を縮めたか区切ったあとに、進めている Issue の番号・spec の名前と段階・審査の往復・タスクの進み・ブランチとPRの番号・答えを待っている問いを所有者に尋ね直していないことと、終わった手順をやり直さず、まだの手順を飛ばしていないことを確かめる。
3. Claude は、この確かめを、直し方がリポジトリの main に入ったあとに、ターミナルの Claude Code の会話と Claude Desktop の会話のそれぞれ1つで1回だけ行い、繰り返さない。Claude は、この spec のPRを、この確かめを待たずに、ほかの要件を満たした時点で出す。
4. Claude は、確かめた結果を、確かめた会話と、読み直した量の最大と、尋ね直しややり直しがあったかどうかとともに所有者に示す。確かめた結果が上限を超えていたか、尋ね直しややり直しがあったときは、Claude は、その会話の箇所も示す。
5. Claude は、この spec のPRを出荷したことを所有者に報告するときに、確かめに使う会話を作ることを、所有者に1回だけ頼む。Claude は、PRがすでにマージされたときも、所有者の承認を待つあいだに Claude が PR の見届けを終えたときも、この報告で、確かめに使う会話を作ることを所有者に頼む。Claude が所有者に頼むことは、PRがマージされたあとに、所有者が、ターミナルの Claude Code と Claude Desktop のそれぞれで、1つの会話で着手から出荷まで進める Issue を1つずつ進めることである。所有者は、2つの Issue を進め終えたら、そのことを Claude に1回伝える。Claude は、所有者に伝えられたときに確かめを行う。所有者が伝えるのは1回だけの作業で、Issue の「やらないこと」が認める一度きりの作業に当たる。
6. Claude が頼んだ Issue を所有者が進めても、会話を縮めたか区切ったことが起きた会話が無かったときは、Claude は、確かめを終えられなかったことと、その理由を所有者に示し、確かめを終わりにする。
