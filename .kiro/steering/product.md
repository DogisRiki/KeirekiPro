# プロダクト概要

KeirekiProは、転職活動中のエンジニアが職務経歴書を作成・管理するためのWebアプリケーション。
Word/Excelでの作成が前提になりがちな職務経歴書を、構造化されたフォーム入力で作成し、
ソフトウェアやOSに依存しないPDF・Markdownとして出力できるようにする。

汎用の経歴書ツールとの違いは、エンジニア固有の情報をデータモデルとして持つこと。
プロジェクトごとの技術スタック(フロントエンド/バックエンド/インフラ/開発支援ツールの分類と
マスタ補完)、担当した作業工程(要件定義〜運用・保守)、チーム構成・役割・成果を
構造化して記録できる。

## 主要な機能

- **複数経歴書の管理**: 1ユーザーが最大50件まで作成でき、経歴書名(ユーザー内で一意)で
  検索・並び替えできる。応募先に合わせた使い分けは「コピーして新規作成」で行う
- **セクション単位の編集**: 基本・職歴・プロジェクト・保有資格・ポートフォリオ・SNS・自己PRの
  7タブ構成。エントリの並び順はポリシーで自動整列される(継続中を先頭、次に終了日の新しい順など)
- **PDF・Markdown出力**: サーバーサイドでThymeleafテンプレートからPDFを生成する。
  フォント種別・各要素のフォントサイズ・表ヘッダー色を設定でき、アプリ内でプレビューできる。
  出力前にドメインルール(氏名・日付・職歴/プロジェクト/自己PR各1件以上)を検査する
- **バックアップとリストア**: 経歴書データをバージョン付きJSONとして書き出し・復元できる
- **自動保存**: 編集中に一定間隔で自動保存する(セッション単位でオン/オフ可能)。
  未保存の変更がある状態での画面遷移はブロックされる
- **認証とアカウント管理**: メールアドレス+パスワード、OIDC(Google / GitHub)、
  メールコードによる二段階認証、パスワードリセット、プロフィール画像アップロード、
  外部連携の解除、アカウント削除

## 想定ユースケース

- 転職活動に向けて職務経歴書を作成し、プロジェクトが増えるたびに追記・更新する
- 同じ経歴データから、応募先ごとに調整した複数の経歴書を管理する
- 構造化データから提出用PDFをレイアウト作業なしで出力する。Markdownで書き出して
  外部(個人サイト・エージェント指定様式)で再利用する
- JSONバックアップでデータを手元に保全する

## ドメイン語彙

集約は「職務経歴書(Resume)」と「ユーザー(User)」の2つ。

| 用語 | コード上の対応 | 意味 |
|---|---|---|
| 職務経歴書 | `Resume`(集約ルート) | 経歴書本体。各セクションのエントリを保持する |
| 経歴書名 | `ResumeName` | ユーザー内で一意。出力ファイル名にも使うため禁則文字がある |
| 職歴 | `Career` | 在籍企業と期間。期間の重複は拒否される |
| プロジェクト | `Project` | 案件経験。概要・チーム構成・役割・成果・作業工程・技術スタックを持つ。期間の重複は許容(兼務があるため) |
| 作業工程 | `process` | 要件定義/基本設計/詳細設計/実装・単体テスト/結合テスト/総合テスト/運用・保守 |
| 技術スタック | `TechStack` | フロントエンド/バックエンド/インフラ/開発支援ツールの分類付き。マスタ(`tech_stack_mst`)による補完あり |
| 期間 | `Period` | 開始年月・終了年月・継続中フラグ |
| 資格 | `Certification` | 資格名と取得年月 |
| ポートフォリオ | `Portfolio` | 成果物名・概要・技術・リンク |
| SNSプラットフォーム | `SnsPlatform` | GitHub/Qiita等の外部プロフィールリンク |
| 自己PR | `SelfPromotion` | タイトルと本文 |
| ユーザー | `User`(集約ルート) | 認証情報とプロフィール。メールアドレスは不変(アカウントの同一性) |
| 外部認証連携 | `AuthProvider` | OIDC連携。`google` / `github` のみ許可 |
| ロール種別 | `RoleName` | `USER` / `ADMIN`。ADMINは二段階認証必須。管理画面は存在しない |

## 補足

- 個人開発の無償ツールであり、課金・プラン機能は存在しない
- 要求モデル(`doc/モデル図/要求モデル.pu`)にある「自動保存の履歴100件保存・復元」は未実装。
  現状の自動保存は通常の更新APIへの書き込みで、履歴は持たない
- 開発プロセス(自律パイプライン)の知識はここには書かない。CLAUDE.mdと `doc/開発フロー/` が正
