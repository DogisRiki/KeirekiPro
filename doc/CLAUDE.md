# doc の作業規約

`doc/` の文書と README を書くときの決まり。文の書き方は `.kiro/settings/rules/owner-writing.md` の `## 決まり` の節にも従う。

## 書き終えたら読み直すこと

README と `doc/` の文書を書き終えたら、次が無いかを読み直す。

- 造語
- 「(5つだけ)」のような、個数を書いた括弧
- 矢印で文と文をつなぐこと(図の中の矢印はよい)
- 見出しに付けた「」の標語

## 手順書

`doc/開発フロー/` の手順書(基盤構築手順、参加者セットアップ手順、並行作業の手順、監査手順など)は、読む人がその文書を見ながら操作するための文書である。

- 手順書には、読む人がすることを、番号を付けた短い手順とコマンドで書く。仕組みの動きや Claude の動きの説明は書かない。仕組みの説明は spec の design.md とスクリプトにあればよい
- 確認役が「動きと合っていない」と指摘したときも、説明を足して合わせず、操作に要らない説明なら消す
- 手順書には、繰り返し使う手順だけを書く。導入のときに1回だけする確認や作業、今の環境から切り替える手順(今の鍵を置き換える、取り消す、作り直す、など)は書かず、導入する PR の本文の「マージのあとにすること」に書く。終わったあとに使われない記述が、手順書に残るためである
- 基盤構築手順と参加者セットアップ手順は、何も無いところから作る形だけを書く
- spec の requirements.md を書く段階で、文書に足す記述を「繰り返し使うもの」と「1回きりのもの」に分ける。過去の spec の形を写す前に、その形が正しいかを確かめる
