# 参加者セットアップ手順

開発に参加する人が、自分のPCごとに行う作業の手順書。上から順に実施する。
PCを再セットアップしたときも、この手順を最初からやり直す。

> 前提: [基盤構築手順](基盤構築手順.md) の「botアカウントの作成とPATの発行」が完了しており、
> botのPATを所有者から受け取っていること。

## 1. CLIのインストール(ホストOS)

### 1-1. GitHub CLI のインストールとログイン

Windows:

```bash
winget install --id GitHub.cli
```

macOS/Linux:

```bash
brew install gh
```

**自分のGitHubアカウント**(botアカウントではない)でログインする:

```bash
gh auth login
```

### 1-2. Claude Code CLI のインストール

Windows:

```bash
winget install Anthropic.ClaudeCode
```

macOS/Linux:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

ターミナルを開き直し、`claude --version` が返ることを確認する。

## 2. コミット・PR作成・push名義の固定

### 2-1. コミット名義の固定(git config)

リポジトリルートで一度だけ実行する:

```bash
git config user.name "DogisRiki-bot"
```

```bash
git config user.email "<botアカウントのnoreplyメールアドレス>"
```

確認する。botのアカウント名が返ればよい:

```bash
git config user.name
```

### 2-2. PR作成名義の固定(bot専用のgh設定ディレクトリ)

bot専用のgh設定ディレクトリを作り、そこへbotアカウントでログインする。
PATはOSの資格情報ストアに入り、設定ファイルには残らない。

ホストOSのターミナルで、**その端末に限って** `GH_CONFIG_DIR` を設定する。

Windows(PowerShell):

```bash
mkdir "$env:USERPROFILE\.gh-bot" -Force
```

```bash
$env:GH_CONFIG_DIR = "$env:USERPROFILE\.gh-bot"
```

macOS/Linux:

```bash
mkdir -p "$HOME/.gh-bot"
```

```bash
export GH_CONFIG_DIR="$HOME/.gh-bot"
```

続けて、同じ端末で **botアカウント**としてログインする:

```bash
gh auth login
```

対話の答えは次のとおり。

| 質問 | 答え |
|---|---|
| Where do you use GitHub? | GitHub.com |
| What is your preferred protocol for Git operations on this host? | HTTPS |
| How would you like to authenticate GitHub CLI? | Paste an authentication token |
| Paste your authentication token | 基盤構築手順で発行したbotのPAT |

次に、リポジトリルートに `.claude/settings.local.json` を作成する。`<user>` は実際のユーザー名にし、
`$HOME` や `%USERPROFILE%` は使わず絶対パスで書く(環境変数は展開されない)。

Windows:

```json
{
    "env": {
        "GH_CONFIG_DIR": "C:\\Users\\<user>\\.gh-bot"
    }
}
```

macOS(Linuxでは `/home/<user>/.gh-bot`):

```json
{
    "env": {
        "GH_CONFIG_DIR": "/Users/<user>/.gh-bot"
    }
}
```

確認は4つとも行う。

1. ログインした端末で次を実行し、botのアカウント名が返ること

```bash
gh api user --jq .login
```

2. ログインした端末で次を実行し、何も出力されないこと(出力されたらPATが平文で保存されている)

Windows(PowerShell):

```bash
Select-String -Path "$env:USERPROFILE\.gh-bot\hosts.yml" -Pattern oauth_token
```

macOS/Linux:

```bash
grep oauth_token "$HOME/.gh-bot/hosts.yml"
```

出力された場合は次を実行してトークンを消し、OSの資格情報ストアが使える状態にしてから
(Linuxではgnome-keyring等のsecret-serviceを起動してから)ログインをやり直す。
平文のまま先へ進まない。

```bash
gh auth logout --hostname github.com
```

3. **新しく開いた**ターミナルで次を実行し、**自分のアカウント名**が返ること。
   返らない場合は、その端末で `gh auth login` をやり直して自分のアカウントに戻す

```bash
gh api user --jq .login
```

4. Claude Codeを再起動し、エージェントに「`gh api user --jq .login` を実行して結果を報告して」と
   依頼して `DogisRiki-bot` が返ること

> 注意: `GH_CONFIG_DIR` を常設の環境変数にしない。Windowsの `setx` も、macOS/Linuxの
> シェルのプロファイルへの追記も不可。人間のターミナルのghとgit pushまでbot名義になる。

> 注意: `.claude/settings.local.json` と `.gh-bot` ディレクトリは、どちらもgit管理外。
> PCの再セットアップ時は両方を作り直す。忘れるとPRが人間の名義になり、
> 保護パスを含むPRがマージ不能になる。

### 2-3. push名義の固定(HTTPS + gh の資格情報ヘルパー)

リモートをHTTPSにし、認証をghへ委ねる。リポジトリルートで一度だけ実行する:

```bash
git remote set-url origin https://github.com/DogisRiki/KeirekiPro.git
```

```bash
git config credential.https://github.com.helper ""
```

```bash
git config --add credential.https://github.com.helper "!gh auth git-credential"
```

2つ目は、グローバル設定のヘルパー(Git Credential Manager等)を打ち消すためのもの。
空を設定してからghのヘルパーを追加しないと、そちらが先に応答して人間の資格情報が使われる。

確認は2つとも行う。

1. Claude Codeのセッションでpushし、成功すること(botのPATが使われる)
2. 人間がターミナルで次を実行し、成功すること(ghのkeyringの自分のアカウントが使われる)

```bash
git push --dry-run
```

> 注意: リモートをSSHにしない。SSH鍵はアカウントに紐づくため、セッション内のpushも
> 鍵の持ち主(人間)名義になり、名義の分離が崩れる。

## 3. Context7 MCP のAPIキーの環境変数設定(ホストOS)

Windows:

```bash
setx CONTEXT7_API_KEY "<Context7のAPIキー>"
```

macOS/Linux はシェルのプロファイル(`~/.zshrc` 等)に追記する:

```bash
export CONTEXT7_API_KEY="<Context7のAPIキー>"
```

ここまでで、参加者セットアップは完了。spec駆動開発のコマンド(`/kiro-*`)とテンプレートは
リポジトリにコミット済みのため、クローンすればそのまま使える。各自のインストール作業は無い。
