# 並行作業の手順

複数のセッションで別々のIssueを同時に進めるときに、所有者がすること。

> 前提: [参加者セットアップ手順](参加者セットアップ手順.md) が完了していること。画面確認が使う `curl` は Git for Windows に同梱されているので、別に入れなくてよい。

## 1. 最初に一度だけ: 共有のサービスを起こす

本体フォルダ(worktree ではないリポジトリの最上位)で打つ。

```bash
docker compose up -d
```

## 2. セッションを開いて着手する

1. worktree を選んでセッションを開く。
   - デスクトップアプリ: セッションを始めるときに、ブランチ名の横の **worktree** を選ぶ
   - CLI: 本体フォルダで `claude --worktree <名前>` を打つ。`<名前>` はセッションごとに変える
2. `/start #N` を打つ。
3. Claude がIssueを分けたときは、部分ごとに 1 と 2 を行い、`/start #<部分の番号>` を打つ。部分のうち1つは、元の会話で打ってよい。

作業を終えたセッションは、デスクトップアプリではサイドバーで保管する(worktree が消える)。

## 3. 同時に走らせる数を変える(必要なときだけ)

品質チェックと画面確認を同時に走らせるセッションの数は、初期値が1である。変えるときは、次を打つ。

```bash
git config keirekipro.parallelSlots <数>
```

`<数>` の目安は、(Docker に割り当てたメモリ − 約1GB)÷ 約4.2GB の小数点以下を切り捨てた数(最小1)。割り当てたメモリは `docker info --format '{{.MemTotal}}'` でバイトの単位で分かる。

## 4. 残ったものを手で片付ける(必要なときだけ)

ふだんは `/start` のたびに Claude が片付けるので、何もしなくてよい。Docker Desktop が動いていなかったときに消せなかったものも、次の片付けがもう一度消しにいく。

手で片付けるときは、Docker Desktop を起動してから、本体フォルダで次を打つ。

```bash
bash .claude/scripts/parallel/session.sh prune
```
