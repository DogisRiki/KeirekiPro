# Redis データ設計

## 1. 二段階認証コード

### 1.1 データ構造

| キー (Key)            | 値 (Value) | 用途                                 |
| --------------------- | ---------- | ------------------------------------ |
| `2fa:{userId}`        | 認証コード | 二段階認証コードを保持する           |

### 1.2 有効期限

- **10 分**（600 秒）経過後に自動削除

---

## 2. 二段階認証チャレンジトークン

### 2.1 データ構造

| キー (Key)                            | 値 (Value)                              | 用途                                                                                          |
| ------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------- |
| `2fa:challenge:{token}`               | `{"userId":"...", "attempts": 0}` のJSON | ログイン成功後に発行する不透明トークンと、対応するユーザーID・失敗試行回数を保持する         |

### 2.2 有効期限

- **10 分**（600 秒）経過後に自動削除

---

## 3. パスワードリセットトークン

### 3.1 データ構造

| キー (Key)                       | 値 (Value)   | 用途                                           |
| -------------------------------- | ------------ | ---------------------------------------------- |
| `password-reset:{token}`         | ユーザーID   | パスワードリセット用トークンが存在するかを判定 |

### 3.2 有効期限

- **10 分**（600 秒）経過後に自動削除
- 確認前のアカウントが、パスワードの再設定を求めて届いた確認のリンクで確認を済ませたときに置くトークンは、確認のリンクの期限までの残りの時間が経過後に自動削除

---

## 4. リフレッシュトークン

### 4.1 データ構造

| キー (Key)                       | 値 (Value)                                                                | 用途                                       |
| -------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------ |
| `refresh-token:{token}`          | Hash: `userId`, `roles`(カンマ区切り), `tokenVersion`                     | 不透明リフレッシュトークンと紐づくユーザー情報を保持 |
| `user-refresh-tokens:{userId}`   | Set: 該当ユーザーが保持するリフレッシュトークン一覧                       | パスワード変更/退会時に一括削除するために使用   |

### 4.2 有効期限

- **7 日**経過後に自動削除

### 4.3 設計意図

- リフレッシュトークン本体を不透明トークン化することで、サーバー側で失効可能にする
- `tokenVersion` をDB(`user_token_versions`)と照合することで、パスワード変更時に旧トークンを無効化できる
- `user-refresh-tokens:{userId}` Setにより、退会・パスワード変更時に該当ユーザーの全トークンを一括削除可能

---

## 5. 確認前の登録

### 5.1 データ構造

| キー (Key)                             | 値 (Value)                                                                    | 用途                                                                         |
| -------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `pending-registration:{id}`            | `{"id":"...","email":"...","passwordHash":"...","username":"...","createdAt":"..."}` のJSON | メールアドレスの確認を済ませる前の登録を保持する。確認を済ませた時点で、同じIDでアカウントを作る |
| `pending-registration:email:{email}`   | Set: そのメールアドレスの確認前の登録のID一覧                                 | ログインと送り直しで、メールアドレスから確認前の登録を探すために使用         |

### 5.2 有効期限

- **24 時間**経過後に自動削除
- `pending-registration:{id}` は、確認のメールを送り直すたびに 24 時間に置き直す
- `pending-registration:email:{email}` は、要素を足すか延ばすたびに 24 時間に置き直す

---

## 6. 最新の確認のリンク

### 6.1 データ構造

| キー (Key)                                 | 値 (Value)                         | 用途                                                                         |
| ------------------------------------------ | ---------------------------------- | ---------------------------------------------------------------------------- |
| `email-verification:current:{subjectId}`   | 最後に送った確認のリンクの `jti`   | 確認のリンクが最新のものかを判定する。`subjectId` は確認前の登録のIDかユーザーID |

### 6.2 有効期限

- 最後に送った確認のリンクの期限が来たら自動削除

### 6.3 設計意図

- 新しい確認のメールを送ると値が置き換わり、前に送ったリンクは使えなくなる
- 確認を済ませるときは、値が同じときだけ消す処理を Lua スクリプト1つで行い、同じリンクが2回使われないようにする

---

## 7. 確認のメールの送信の間隔

### 7.1 データ構造

| キー (Key)                          | 値 (Value) | 用途                                                       |
| ----------------------------------- | ---------- | ---------------------------------------------------------- |
| `email-verification:rate:{email}`   | `1`        | 同じメールアドレスへの確認のメールを1分に1回に抑える       |

### 7.2 有効期限

- **60 秒**経過後に自動削除
