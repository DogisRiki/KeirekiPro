# 障害時の本番操作手順

障害のときに、所有者が AWS を変える手順。所有者は、CLI なら「1」、マネジメントコンソールなら「3」から始める。

- 所有者は、状態を調べるだけなら(見るだけ)、普段のターミナルで `aws login` して調べる。この調べものは Claude と一緒に進められる
- AWS を変える操作は、普段のターミナルと普段のマネジメントコンソールでは拒まれる。所有者は、変えるときだけ「1」か「3」で変更用ロール `keirekipro-ops` に切り替える

> 前提: 所有者が、普段のターミナルで `aws login` していること(「1」で使う)。
> ops-shell の設置は、[参加者セットアップ手順](../../開発フロー/参加者セットアップ手順.md) の「5. 本番を変えるターミナル(ops-shell)の設置」で済ませてある。

## 1. ops-shell で AWS を変える(CLI)

1. 所有者は、スタートメニューの「KeirekiPro ops」を開き、Windows の確認の画面(ユーザーアカウント制御)で「はい」を押す
2. 所有者は、`Enter the 6-digit code from the authenticator app` と出たら、認証アプリの `keirekipro` の6桁を入れる(入れた数字は画面に出ない)
3. 所有者は、緑の文字で `This window now uses the role keirekipro-ops` と、鍵の期限(`The keys expire at`)が出ることを確かめる
4. 所有者は、同じウィンドウで aws コマンドを打つ。`--profile` は付けない。例:

```powershell
aws rds start-db-instance --db-instance-identifier <DBの識別子>
```

5. 所有者は、作業が終わったらウィンドウを閉じる

1 から 2 のあいだに次の表示が出たときは、所有者は右の操作をする。

| 表示 | 所有者の操作 |
|---|---|
| `No keys were set. Type ops-renew to enter the code again.` | 同じウィンドウで `ops-renew` を打ち、新しい6桁を入れる |
| `The code must be 6 digits.` | 同じウィンドウで `ops-renew` を打ち、6桁を入れ直す |
| `The aws login session has expired.` | 普段のターミナルで `aws login` してから、ops-shell のウィンドウで `ops-renew` を打つ |
| `ops-shell must run as an administrator.` | Enter を押してウィンドウを閉じ、スタートメニューの「KeirekiPro ops」を右クリックして「管理者として実行」で開き直す。障害の対応が終わったら、参加者セットアップ手順の「5-2」をやり直して、項目に「管理者として実行」を付け直す |

## 2. 15分を過ぎたとき(ops-renew)

ops-shell の鍵は、6桁を入れてから15分で切れる。切れると、aws コマンドが `ExpiredToken` で失敗する。

1. 所有者は、同じウィンドウで `ops-renew` を打つ。`cd` で別の場所に移らずに打つ
2. 所有者は、新しい6桁を入れ、`This window now uses the role keirekipro-ops` と出ることを確かめる
3. 所有者は、aws コマンドを打ち直す

所有者は、ops-shell のウィンドウでは `cd` で別の場所に移らない。移ってしまったときは、所有者は `ops-renew` を打たずにウィンドウを閉じ、「1」の 1 からやり直す。

## 3. マネジメントコンソールで AWS を変える

所有者は、アカウントの番号を、[手動作業手順](手動作業手順.md) の「1.2.1 IAMユーザーと変更用ロールの作成(ルートユーザー)」の 9 で控えた番号から取る。
控えが手元に無いときは、所有者は普段のターミナルで次を打って出す:

```bash
aws sts get-caller-identity --query Account --output text
```

1. 所有者は、マネジメントコンソールにサインインしていればサインアウトする
2. 所有者は、「IAM ユーザー」を選び、アカウントの番号、ユーザー名 `keirekipro`、パスワード、認証アプリの6桁を入れてサインインし直す
3. 所有者は、サインインしてから1分以内に、右上のユーザー名 →「ロールの切り替え」をクリックし、
   アカウント ID にアカウントの番号、IAM ロール名に `keirekipro-ops` を入力して「ロールの切り替え」をクリックする
4. 所有者は、右上に `keirekipro-ops` が出ることを確かめてから、AWS を変える
5. 所有者は、作業が終わったらサインアウトする

3 で拒まれたとき(1分を過ぎたとき)と、作業の途中で切り替えが切れたときは、所有者は 1 からやり直す。

## 4. 切り替えられないとき・拒まれたとき

### 4.1 変更用ロールで `AccessDenied` と出たとき

所有者は、まず `aws sts get-caller-identity --query Arn --output text` を打ち、出力に `assumed-role/keirekipro-ops/` が含まれるかを見る。含まれなければ、変更用ロールに切り替わっていないので、「1」からやり直す。

変更用ロールでも、IAM の利用者・ロール・ポリシーを作る・変える・消す操作と、サービス用のロールを作る・消す操作は拒まれる。所有者は、その操作を次のどちらかで行う。

- Terraform で管理しているものは、GitHub の Actions の画面から `terraform-apply.yaml` を起動して変える
- それ以外は、AWS のルートユーザーでマネジメントコンソールにサインインして変える

### 4.2 変更用ロールに切り替えられないとき

所有者は、6桁を入れ直しても、サインインし直しても「1」や「3」で切り替えられないときは、ルートユーザーで権限を直す。

1. 所有者は、[手動作業手順](手動作業手順.md) の「1.2.1 IAMユーザーと変更用ロールの作成(ルートユーザー)」の 1 から 3 のとおりに、
   ルートユーザーで CloudShell を開き、アカウントの番号を取り、ポリシーの JSON の場所に移る。
   3 の `git clone` が `already exists` で失敗したら、所有者は `git -C KeirekiPro pull` を打ってから `cd` する
2. 所有者は、次の2つを打ち、`keirekipro-readonly-guard` と、`keirekipro-ops` の信頼ポリシーをリポジトリの内容に戻す:

```bash
aws iam put-user-policy --user-name keirekipro --policy-name keirekipro-readonly-guard \
  --policy-document "$(sed "s/<ACCOUNT_ID>/$ACCOUNT_ID/g" keirekipro-readonly-guard.json)"
aws iam update-assume-role-policy --role-name keirekipro-ops \
  --policy-document "$(sed "s/<ACCOUNT_ID>/$ACCOUNT_ID/g" keirekipro-ops-trust.json)"
```

3. 所有者は、同じ節の 8 の表のコマンドを1つずつ打ち、表の出力と違う行を直す
   - 管理ポリシーが足りない行: 同じ節の 5 と 7 の `aws iam attach-` で始まるコマンドのうち、足りないものを打つ
   - MFA の行が出ない: 同じ節の 6 のとおりに、MFA を登録し直す
4. 所有者は、8 の表の出力がすべて合うことを確かめ、CloudShell を閉じてルートユーザーからサインアウトする
5. 所有者は、「1」か「3」で切り替え直す
