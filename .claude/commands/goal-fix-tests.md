---

テスト修復に向けたゴール駆動の作業を開始する。対象: $ARGUMENTS

## 達成条件(満たしたら終了する)

- 対象領域のテストコマンドが exit 0 で成功している
  - frontend: `docker compose exec -u node -w /home/node/app frontend pnpm test`
  - backend: `docker compose exec -w /home/spring/app backend ./gradlew test`
- 既存テストファイルの削除・skip化・アサーション削除を行っていない

## 上限

- 最大8ターン。上限に達しても未達成の場合は、失敗しているテストと原因の分析を報告して
  人間の判断を仰ぐ。上限を自分の判断で増やして続行しない

## 禁止事項

- テストのskip/only/@Disabledの追加
- アサーションの削除・弱体化(期待値をテストが通る値に書き換えるだけの修正を含む。
  期待値が誤っていた場合は、その根拠を報告に含める)
- テストファイルそのものの削除

## 運用

- 対象は小さく絞る(1テストファイル程度)。失敗が広範囲に及ぶ場合は、原因の切り分け結果を報告して分割を提案する
- 修正はまず「テストが正しいか、実装が正しいか」の判断から始め、判断根拠を報告に含める
- 終了時に、達成/未達成・かかったターン数を報告し、人間に /usage でのコスト確認を促す
