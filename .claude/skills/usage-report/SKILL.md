# usage-report

このスキルは、Claude が、Issue ごとの AI の作業の集計を GitHub に出すときの手順を定める。このスキルは、`usage.sh` を呼ぶ順と、所見の書き方と、直す案の尋ね方と、失敗したときに Claude が会話の相手に書く中身を定める。作業時間やトークン数の数え方は、`.claude/scripts/usage/` のスクリプトが決める。このスキルは数え方を定めない。

## 守ること

- Claude は、集計を出すために、所有者にも開発者にもコマンドを打つよう頼まない。このスキルのコマンドは、すべて Claude が打つ。
- Claude は、Issue の作業の途中では、使用料や AI の作業時間がいつもより増えても、集計も所見も作らない。Claude が集計を作るのは、下の「いつ使うか」の4つの時点だけである。
- Claude は、このスキルのコマンドを、そのセッションの作業フォルダの最上位で、1つずつ打つ。下の手順の `usage.sh` は `bash .claude/scripts/usage/usage.sh` を指す。
- コマンドの `<ID>` は、この会話の ID である。Claude は、会話の始めに SessionStart のフックが渡した `[parallel] このセッションのID: <ID>` の文から、ID を取る。文が見つからなければ、Claude は、`--session <ID>` を付けずに呼ぶ。
- コマンドの `<N>` は、集計する Issue の番号である。
- `usage.sh` は、成功したときに 0 で、何もしなかったときに 2 で、失敗したときに 1 で終わる。失敗したときは、`usage.sh` が標準エラーに理由を日本語の1文で出す。Claude は、会話の相手に書く文に、終了コードの数を書かず、何が起きたかを書く。

## いつ使うか

### マージを見届けたとき

`/ship` の CI の見届けで、PR の `state` が `MERGED` だと分かり、PR の本文の行頭に `Closes #<N>` があるときである。Claude は、同じ会話の中で、その Issue について、下の「集計を出す手順」を行う。

### 次の会話で出すとき

会話の始めのフックが、`[usage] Issue #<N> を閉じる PR がマージされ、集計がまだ GitHub に出ていない。` の文か、`[usage] Issue #<N> の集計は GitHub に出したが、一覧か案の索引への書き込みが残っている。` の文で、Issue を知らせたときである。Claude は、会話の相手の最初の依頼に答える前に、知らされた Issue ごとに、下の「集計を出す手順」を行う。書き込みが残っている Issue では、手順の1の `usage.sh draft` が、残った一覧の行と案の索引を書き足して、2 で終わる。Claude は、知らされたすべての Issue の手順を終えてから、会話の相手の最初の依頼に答える。

### 案を尋ねるとき

会話の始めのフックが、まだ答えていない案があると知らせたときである。Claude は、`usage.sh proposals --session <ID>` を呼び、下の「案を尋ねる手順」のとおりに、案ごとに起票するかを尋ねる。

### 所有者かを尋ねるとき

次の2つのどちらかに当たるときである。

- 会話の始めのフックが、この PC で Claude と話す人が所有者かどうかがまだ決まっていないと知らせたとき
- 案があるときに、`usage.sh publish` の出力の `owner` が `unknown` だったとき

Claude は、会話の相手に、このリポジトリの所有者かどうかを、チャットの本文で1回だけ尋ねる。会話の相手が所有者だと答えたら、Claude は、`usage.sh owner yes --session <ID>` を呼び、続けて上の「案を尋ねるとき」の手順に進む。会話の始めのフックは、所有者かどうかが決まっていない PC では案を知らせないので、Claude は、`usage.sh proposals` の出力で案を知る。会話の相手が所有者でないと答えたら、Claude は、`usage.sh owner no --session <ID>` を呼び、案を尋ねない。

## 集計を出す手順

1. Claude は、`usage.sh draft <N> --session <ID>` を呼ぶ。
   - 2 で終わったときは、Claude は、Issue #<N> の集計を作らなかったことを、会話の相手に1文で書いて、この手順を終える。集計を出し済みの Issue でも、`usage.sh draft` は 2 で終わる。そのときは、`usage.sh draft` が一覧の行と案の索引も確かめて書き足しているので、Claude はほかに何もしない。
   - 1 で終わったときは、Claude は、下の5に進む。
   - 0 で終わったときは、`usage.sh draft` が、`{"draft":<下書きの場所>,"compare":{...},"unknown":{...}}` の1行を出す。Claude は、2に進む。
2. Claude は、下書きの場所の `report.md` と `compare.json` を読み、下の「所見の決まり」のとおりに、所見のファイルを scratchpad に書く。
   - `usage.sh draft` の出力の `unknown` に値があれば、それは、会話の記録を抜き出す部品 `extract.pl` が見分けられなかった、会話の再開のきっかけの値と回数である。そのとき、Claude は、`usage.sh publish` を呼ぶ前に、その値と回数と、そのために作業時間が実際より長く数えられたことがあることを、会話の相手にチャットで書く。Claude は、あわせて、`extract.pl` の会話の再開のきっかけの値の一覧にその値を足す案を、所見のファイルの直す案に書く。
3. Claude は、`usage.sh publish <N> --findings <所見のファイル> --session <ID>` を呼ぶ。
   - 0 で終わったときは、`usage.sh publish` が、`{"failed":[...],"owner":"yes|no|unknown","proposals":[...],"url":<集計のコメントの URL>}` の1行を出す。Claude は、集計を出したことと、集計のコメントの URL を、会話の相手に書く。`failed` に `list` があれば、Claude は、一覧の Issue に行を書けなかったことを書く。`failed` に `proposals` があれば、Claude は、案の索引に案を書けなかったことを書く。どちらのときも、Claude は、次の会話で書き足されることも書く。
   - 2 で終わったときは、Claude は、Issue #<N> の集計がすでに出ていたので出さなかったことを、会話の相手に1文で書いて、この手順を終える。
   - 1 で終わったときは、Claude は、下の5に進む。
4. `usage.sh publish` の出力の `proposals` に案の ID があれば、Claude は、出力の `owner` の値ごとに、次にすることを分ける。
   - `yes` のときは、Claude は、下の「案を尋ねる手順」を行う。
   - `no` のときは、Claude は、案を尋ねない。案は、所見に残る。所有者が次に Claude の会話を始めたときに、会話の始めのフックが案を知らせる。
   - `unknown` のときは、Claude は、上の「所有者かを尋ねるとき」の手順に進む。
5. `usage.sh draft` か `usage.sh publish` が 1 で終わったときは、Claude は、集計を GitHub に出せなかったことと、標準エラーに出た理由を、会話の相手に書く。Claude は、あわせて、この PC で次に Claude の会話を開いたときに、Claude が集計を出し直すことを書く。
6. 3で `usage.sh publish` が 0 で終わったときは、Claude は、4の案の扱いを終えたあとに、下の「料金表に価格を足す手順」を行う。案が無かったときは、Claude は、3のあとすぐに、その手順を行う。

## 料金表に価格を足す手順

この手順は、集計で価格が分からなかったモデルの価格を、公式の料金ページから料金表 `.claude/scripts/usage/usage-config.json` に足す PR を作り、PR がマージされるか閉じられるまで見届ける手順である。Claude は、この手順で、集計のスクリプトと集計の表を変えない。Claude は、この手順で、Issue を起票しない。Claude は、この手順で、所有者に PR の承認のほかの作業を頼まない。

1. Claude は、`usage.sh draft` が出した下書きの場所の `report.json` を読み、`totals.usd_unknown_models` から「不明」を外したモデルの ID を対象にする。対象が無ければ、Claude は、この手順を終える。
2. Claude は、対象のモデルごとに、次のコマンドの `<ID>` をモデルの ID にして実行し、同じモデルの価格を足す PR が開いているかを確かめる。番号が返ったモデルを、Claude は対象から外す。対象が無くなれば、Claude は、この手順を終える。`gh` が失敗したら、Claude は、PR を作らずに、失敗したことと理由を会話の相手に書いて、この手順を終える。

   ```bash
   gh pr list --state open --limit 200 --json number,body --jq '[.[] | select(.body | contains("- 料金表に価格を足したモデル: `<ID>`")) | .number]'
   ```

3. Claude は、作業フォルダの最上位(`git rev-parse --show-toplevel` の出力)を覚え、`git fetch origin main` を実行する。Claude は、続けて、最上位で `git worktree add -b chore/usage-prices-<YYYYMMDD> .claude/worktrees/usage-prices-<YYYYMMDD> origin/main` を実行する。`<YYYYMMDD>` は今日の日付である。同じ名前のブランチか worktree があれば、Claude は、名前の末尾に `-2`、`-3` を付ける。Claude は、次に、`cd` だけのコマンドで、その worktree に移る。`git worktree add` が失敗したら、Claude は、PR を作らずに、失敗の理由を会話の相手に書いて、この手順を終える。
4. Claude は、公式の料金ページ `https://platform.claude.com/docs/en/about-claude/pricing` を WebFetch で読み、読んだ日を覚える。WebFetch を使えない会話では、Claude は、web-fetch の補助役にページを読ませる。ページを読めなかったら、Claude は、PR を作らずに、下の11のとおりに worktree を片付け、ページを読めなかったことを会話の相手に書いて、この手順を終える。
5. Claude は、worktree の `.claude/scripts/usage/usage-config.json` を、次のとおりに直す。
   - Claude は、モデルの ID の末尾の `-<8桁の日付>` を外した名前を、料金表のキーにする。集計のスクリプトが、日付を外した名前でも価格を引くためである。Claude は、ID を、系統と版で、ページのモデルの名前に読み替える。たとえば、Claude は、`claude-fable-5-2` を「Fable 5.2」に読み替える。
   - 料金表に無いモデルには、Claude は、ページに載っている種類の価格をすべて足す。足す種類は、`in` `cw5` `cw1h` `cr` `out` と、ページに速い出力の価格があれば `fast` と、ページに入力の長さで価格が変わる段があれば `long_input` である。料金表にあるモデルには、Claude は、ページに載っていて料金表に無い種類の価格だけを足す。
   - ページが値で載せている価格には、Claude は、その値を使う。ページが倍率で示している価格(速い出力のキャッシュの3つ)には、Claude は、ページに書かれた倍率を速い出力の入力の価格に掛けた値を使う。
   - ページに載っていないモデルについては、Claude は、料金表に何も足さず、そのモデルを「価格が見つからなかったモデル」として覚える。
   - ページにモデルが載っていても、料金表に無い種類の価格がページに無いモデルについては、Claude は、料金表に何も足さず、そのモデルを「料金表とページを突き合わせても足す価格が無かったモデル」として覚える。origin/main の料金表にすでに価格があるモデルと、集計に要る種類の価格がページに無いモデルが、これに当たる。
6. 価格を1つも足さなかったときは、Claude は、料金表のほかのモデルの突き合わせと `prices.checked_on` の書き換えをせず、PR を作らない。Claude は、作業フォルダの最上位に `cd` で戻り、`git worktree remove <worktree>` と `git branch -D <ブランチ>` を実行する。Claude は、価格が見つからなかったモデルと、突き合わせても足す価格が無かったモデルの名前を会話の相手に書いて、この手順を終える。価格を1つ以上足したときは、Claude は、料金表に次の2つを書く。
   - Claude は、料金表にあるほかのモデルのうち、ページに載っているモデルの価格をページと突き合わせ、違う値をページの値に直す。Claude は、直したモデルと種類と、直す前と後の値を覚える。ページに載っていないモデルの価格を、Claude は変えない。
   - Claude は、`prices.checked_on` を読んだ日にする。ページの場所が `prices.source` と違えば、Claude は、`prices.source` を読んだ場所にする。
7. Claude は、worktree で `bash .claude/scripts/usage/tests/test-report.sh` を流す。価格を直したために既存の場合の期待の値が外れたら、Claude は、期待の値を新しい価格で求め直した値に直し、直したことを PR の本文の `Test-Change-Justification` に書く。Claude は、続けて、`/ship` の手順1(verify と push の前の3つの検査)を worktree で行う。
8. Claude は、`/ship` の手順3と手順4のとおりに、worktree を作業のフォルダにして、`git commit -F <scratchpad のメッセージのファイル>` と `git push -u origin <ブランチ>` を、それぞれ単独のコマンドで実行する。メッセージは `.commit_template` に従い、prefix を `chore` に、`Refs:` を `N/A` にする。
9. Claude は、PR の本文を下の見本の形で scratchpad のファイルに書き、`gh pr create --base main --head <ブランチ> --title "chore: 作業の集計の料金表に <モデルの名前> の価格を足す" --body-file <本文のファイル>` を実行する。本文に `Closes` を書かない。
10. Claude は、worktree を作業のフォルダにしたまま、`/ship` の手順6(自動マージの予約の確認)と手順7(CI の見届け)を行う。手順7の所有者の承認待ちでは、Claude は、`wait-approval.sh` を裏で動かし、承認を待っていることを会話の相手に書く。CI が赤になったら、Claude は、worktree で直して push する。同じ失敗が3回続いたら、Claude は、止めて報告する。
11. PR がマージされたか、所有者が PR を閉じたら、Claude は、作業フォルダの最上位に `cd` で戻り、`git worktree remove <worktree>` と `git branch -D <ブランチ>` を実行する。所有者が閉じた PR を、Claude は作り直さない。次の集計でそのモデルの価格がまだ分からなければ、Claude は、その集計のときに、この手順に従って PR をもう一度作る。
12. Claude は、PR の URL と、価格を足したモデルと、価格が見つからなかったモデルと、突き合わせても足す価格が無かったモデルの名前を、会話の相手に書く。

Claude は、この手順の状態をファイルに持たない。同じモデルの PR が開いているかを、Claude は、そのたびに GitHub の PR の本文から読む。

### PR の本文の見本

```markdown
## 概要

作業の集計で価格が分からなかったモデルの公表価格を、公式の料金ページから料金表に足す。

## 足した価格

- 料金表に価格を足したモデル: `claude-fable-5-3`
  - 入力 8、5分のキャッシュの書き込み 10、1時間のキャッシュの書き込み 16、キャッシュの読み込み 0.2、出力 40(100万トークンあたりの米ドル)
  - 速い出力: 入力 16、5分のキャッシュの書き込み 20、1時間のキャッシュの書き込み 32、キャッシュの読み込み 0.4、出力 80(キャッシュの3つは、ページの倍率で求めた)

## 直した価格

- `claude-opus-5-5` の出力: 20 → 18

## 読んだ公式の料金ページ

- 場所: https://platform.claude.com/docs/en/about-claude/pricing
- 読んだ日: 2026-12-01

## 価格が見つからなかったモデル

- `claude-xxx-9`(ページに載っていない)

Refs: N/A
```

- 「足した価格」の節には、いつも1つ以上のモデルがある。Claude は、価格を1つ以上足したときだけ PR を作るためである。
- 直した価格が無いときは、Claude は、「直した価格」の節に「無し」と書く。価格が見つからなかったモデルが無いときは、Claude は、「価格が見つからなかったモデル」の節に「無し」と書く。
- `- 料金表に価格を足したモデル: ` の行は、上の2で開いている PR を探すときに使う。Claude は、この行を、モデルごとに1行ずつ、この形のまま書く。

## 案を尋ねる手順

1. Claude は、`usage.sh proposals --session <ID>` を呼ぶ。出力は、`[{"id":<案の ID>,"issue":<Issue の番号>,"text":<案の文>}, ...]` の1行である。
2. Claude は、案ごとに、Issue の番号と案の文を書き、起票するかどうかを、チャットの本文で所有者に尋ねる。Claude は、ボタン付きの質問で尋ねない。案の文を読まないと答えられない問いだからである。
3. 所有者が起票すると答えた案では、Claude は、file-issue のスキルの決まりで起票し、起票したあとに `usage.sh proposal <案の ID> filed --session <ID>` を呼ぶ。
4. 所有者が起票しないと答えた案では、Claude は、`usage.sh proposal <案の ID> declined --session <ID>` を呼ぶ。Claude は、起票しないと答えた案を、もう一度尋ねない。
5. 所有者が起票すると答えるまで、Claude は案を起票しない。所有者が答えなかった案は、まだ答えていない案として残る。Claude は、その案について `usage.sh proposal` を呼ばない。

## 所見の決まり

所見のファイルは、Issue の集計のコメントの最後の「### 所見」の見出しの下に入る。Claude は、所見のファイルに、目立つ点の箇条と、直す案の節だけを書く。Claude は、見出し「### 所見」を、所見のファイルに書かない。見出しは `usage.sh publish` が付ける。

### 目立つ点の書き方

Claude は、目立つ点を、下書きの `compare.json` から、次の決まりで書く。`compare.json` は、`past_rows`(この Issue より前に終わった一覧の行の数)と、値ごとの `name` `value` `value_text` `median` `median_text` `ratio` `rows` を持つ。`rows` は、`past_rows` の行のうち、その値を数えられた行の数である。

- `past_rows` が 0 のときは、Claude は、目立つ点の箇条に「- 比べる過去の集計が無い。」の1行だけを書く。
- `ratio` が1.5以上か0.67以下の値ごとに、Claude は、「- <name>は <value_text> で、過去 <rows>件の中央値 <median_text> の <倍率>倍だった。」の1行を書く。倍率は、`ratio` を小数1桁に四捨五入した数である(例: `ratio` が 2.4853 なら 2.5)。
- `median` が 0 で `value` が1以上の値ごとに、Claude は、「- <name>は <value_text> で、過去 <rows>件の中央値は 0 だった。」の1行を書く。
- 作業時間とトークン数と使用料の行には、Claude は、その値が最も大きい段階か、モデルと役割の組を、「<段階の名前>の段階が <数> だった。」か「<モデル> の <役割>が <数> だった。」の1文で添えてよい。Claude は、この1文の数に、`report.md` の表の値を写す。
- 目立つ点が1つも無いときは、Claude は、「- 過去 <past_rows>件と比べて、中央値の1.5倍以上か0.67倍以下の値は無かった。」の1行を書く。
- Claude は、`value_text` と `median_text` の文字を、そのまま写す。Claude は、数を自分で書き直さない。

### 直す案の書き方

- Claude は、所見から開発の仕組みを直す案を作ったら、目立つ点の箇条のあとに、見出し「### 直す案」を置き、その下に「- [<Issue の番号>-<連番>] <案の文>」の形で書く。連番は、その Issue の案の中で1から振る。
- 案が無ければ、Claude は、見出し「### 直す案」も書かない。
- Claude は、案を所見に書いても、所有者が起票すると答えるまで起票しない。

### 書いてよい中身と書かない中身

このリポジトリは公開されているので、集計のコメントは誰でも読める。

- Claude は、所見と案の文に、会話の文、ファイルの中身、コマンドの出力、PC の中のファイルの場所とユーザー名を書かない。`usage.sh publish` は、所見のファイルに手元の場所と PC のユーザー名と git の user.email の値があると、集計を出さずに 1 で終わる。
- Claude は、所見と案の文で作業に触れるときは、段階と表の項目の名前で触れ、会話の文を引かない。
- Claude が所見と案の文で使ってよい言葉は、次のものである。
  - 段階の名前: 着手の判断、要件、要件の審査、設計、設計の審査、タスク、タスクの審査、実装、実装中の spec の直し、出荷とレビュー対応、その他
  - 表の項目の名前: `report.md` の表の見出しと行の名前(AIの作業時間、トークン数、使用料、待ち時間、実装中に spec へ戻った回数など)
  - モデルと役割の名前: `report.md` のモデルごとの表に書かれたモデルの ID と役割の名前
  - 数: `compare.json` と `report.md` に書かれた数
- Claude は、所見と案の文を、`.kiro/settings/rules/owner-writing.md` の決まりで書く。
