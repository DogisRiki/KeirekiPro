# request

要望の壁打ちの入口。**打たれた時点が壁打ちの開始。** 所有者が決めたことを出どころ付きで記録し、最後に `file-issue` スキルへ引き渡して起票する。

`/request` は要望の起点のためのコマンドであり、起票全般を受け持つものではない。作業中に見つけた問題の起票や、所有者の「起票して」は、`/request` を通らずに `file-issue` スキルで行う。

出どころの種類、本文の書式、起票前の確認は `file-issue` スキルに定めてある。**このスキルでは種類を増やさず、壁打ちでの答えへの当てはめ方だけを書く。**

## 記録ファイル

- 置き場所: scratchpad の `request-log.md`
- 追記のみ。書いた行を書き換えない。決定が覆ったときは、覆ったことを新しい行で追記する
- 同じ会話で `/request` がもう一度打たれたら、既存の記録ファイルに追記して続ける。別の会話では新しく作る

次の3つの節に分けて書く。要望が複数あるときは、要望ごとに見出しを分け、その下に3つの節を置く。

```markdown
## 決定

- 決めたこと: <内容>
  - 出どころ: <file-issue の出どころのいずれか。ただし「AIの補い」を除く>
  - 根拠: <所有者の発言の要旨、ファイルと行、URLなど>

## 調べた事実

- <事実>(根拠: <ファイルと行、コマンド、URL>)

## 未決

- <決まらなかった点>
```

「決定」の節には所有者が決めたことだけを書く。AIの補い(所有者がまだ何も言っていないこと)は「決定」に書かない。「調べた事実」と「未決」は壁打ちの間だけ使い、Issueには載せない。

## 手順

### Step 1: 準備

1. `.claude/skills/file-issue/SKILL.md` を読む
2. 記録ファイルが無ければ作る。あれば読んで続きから始める
3. 引数に話題があれば、それを出発点にする

### Step 2: それまでの会話から拾う

`/request` が打たれる前の会話で決まったことがあれば、記録ファイルの「決定」に書く。出どころは「会話から拾った(記録なし)」にする。

### Step 3: 聞き取る

決めることが尽きるまで尋ねる。質問の数に上限は置かない。

#### 尋ねる範囲

Issue本文の「困っていること」「やりたいこと」「どうなれば解決か」「やらないこと」に入ることだけを尋ねる。「きっかけ」は所有者の言葉を引くものなので尋ねない。「決めた方式」はAIから尋ねない。

所有者が見て「できた」と言える状態(画面に何が出るか、何が保存されるか、何ができるか)は尋ねる。それをどう作るか(画面の項目の並び、データの持ち方、API、処理の方式)は尋ねない。気づいたら記録ファイルの「未決」に書く。Issueには書かず、仕様を決める段階で改めて考える。所有者が自分から方式を決めたときは、「決定」に書く。

#### 質問にしてよい条件

次のすべてを満たすものだけを質問にする。満たさないものは出さない。

- 答えによって、Issue本文のどこかが変わる。変わる見出しを言えない質問は出さない
- 決めるのが所有者である。調べれば分かることは尋ねず、AIが調べる
- 上の「尋ねる範囲」に入る

推奨も同じ範囲に収める。どう作るかを推奨に書かない。

#### 進め方

1. 決めることを、親子関係のある一覧として捉える。親は要望そのもので、子は親が決まって初めて意味を持つ決めごとである
2. 最初の回で、その時点で見えている決めごとを短い一覧で示し、そのうえで質問を出す。この一覧は答えが返るたびに増えるもので、尋ねることの上限ではない
3. 回ごとに、その時点で尋ねられる質問をすべてまとめて出す。尋ねられる質問とは、前提になる決めごとがすでに決まっている質問を指す。ほかの質問の答えで中身が変わる質問は、同じ回に入れず後の回に回す
4. 質問に要る事実は、先に調べる(リポジトリの実ファイル、Issue、公式ドキュメント)。調べるのに時間がかかるときはサブエージェントに任せ、その事実に依存しない質問は先に出す。調べた事実は記録ファイルの「調べた事実」に書く
5. 回を出したら、所有者の答えを待つ。答えが返ったら、記録ファイルの「決定」に追記し、一覧を組み直して次の回を出す
   - 出どころ: 推奨やAIが示した選択肢をそのまま選んだ答えは、file-issue の「AIの提案を了承」にあたる。選択肢に無い答えや、選択肢を直した答えは「所有者の発言」にあたる
   - 答えの無かった質問は、決まっていないものとして次の回にもう一度出す。無回答を推奨の了承と読まない
   - 答えによって前に決めたことが揺らいだら、その決めごとを決まっていないものに戻し、次の回で尋ね直す
   - 答えの中に、一覧に無い要素が出てきたら、次の回でその要素を尋ねる。同じ要望に含めるか別の要望に分けるかも、所有者が決めることなので同じ回で尋ねる
   - 「未決」に書いた点が後で決まったら、「未決」の下に「決まった(決定の節を見る)」と追記する
6. 回の途中で起票の案を書かない。書くのは記録ファイルだけにする

回の書式は次のとおり。所有者が番号ごとに答えられるようにする(例: 「1は推奨どおり、2は2番、3は反対でこうしたい」)。

```markdown
**Q1. <題>**
<質問の本文。選択肢があれば番号を付ける>
推奨: <推奨する答えと、その理由>
変わる所: <答えで変わるIssue本文の見出し。要望を分けるかの質問は「要望の分け方」と書く>

---

**Q2. <題>**
...
```

#### 終わり方

次のどちらかで終える。

- 条件を満たす質問が尽きた: 尽きたと判断する前に、次を点検する。点検で質問が出たら、次の回として出す
  - 「困っていること」「やりたいこと」「どうなれば解決か」「やらないこと」の見出しごとに、所有者が決めた内容があるか。無い見出しがあれば、それが次の質問になる(「困っていること」と「やりたいこと」は、どちらか一方にあればよい)。所有者が「特に無い」と答えた見出しは、その答えを「決定」に書き、内容があるものとして数える(本文ではその見出しを省く)
  - 「やりたいこと」に、ほかに含めたいものが無いかを一度は尋ねたか

  点検を終えても質問が出なければ、決まったことと「未決」を一覧で示し、「認識は揃いましたか」と確認する。了承を得たら Step 4 へ進む。直しや追加を言われたら、進め方の5に戻る
- 所有者が「もう起票して」「切り上げて」と言った: そこで打ち切り、尋ねていない点を「未決」に書く。「未決」をチャットで一覧にして示してから Step 4 へ進む(Issueには載せない)

### Step 4: 引き渡す

記録ファイルを持って `file-issue` スキルの手順に進む。起票の案を見せる確認と起票は、file-issue の手順で行う。

file-issue の確認で、所有者が新しい要素を足したり、まだ決めていないことに触れたりしたら、Step 3 に戻ってその点を尋ねる。記録ファイルに追記してから、file-issue の手順をやり直す。file-issue の中で本文に書き足して済ませない。

## 制約

- 所有者の答えを待たずに、決まったこととして記録しない
- AIが自分で決めごとに答えて先へ進まない。推奨は出すが、決めるのは所有者である
