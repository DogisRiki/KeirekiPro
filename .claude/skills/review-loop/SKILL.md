# review-loop

## Job

Codexクロスレビューの指摘対応ループ。指摘の分類・修正・push・再レビュー(自動発火)・判定確認を、
**コード品質とspec適合の両方がLGTMになるまで** 繰り返す。

**codex-reviewが赤になったら必ずこのスキルを起動する。** 場当たりに指摘へ対応しない。

往復の上限は5回で、`codex-review.yml` が機械的に打ち切る。6回目以降はレビューが実行されず、
チェックは赤のまま止まる。回数は**headブランチ単位**で数えるため、PRを閉じて開き直しても
リセットされない。

## Steps(1往復 = 以下の1〜6)

1. **指摘の取得**: `gh pr view <PR番号> --comments` で最新の「Codex Review」コメントを読む。
   `gh pr checks <PR番号>` で codex-review ジョブの状態も確認する。

2. **分類**: 各指摘を次の3種に分類する:
   - **本修正**: 正しい指摘。コードを修正する
   - **妥当なnit**: 正しいが軽微。原則対応する(対応コストが高い場合は理由を記録して見送り可)
   - **誤検知**: 指摘が事実誤認・文脈の見落としである。**却下の根拠を具体的に説明できる場合のみ**

3. **誤検知処理**: 1件でも誤検知と判定した場合:
   - `gh pr edit <PR番号> --add-label codex-overruled`(ラベルが無ければ
     `gh label create codex-overruled --description "Codex指摘をClaudeが誤検知と判定したPR(週次監査の優先サンプリング対象)" --color FBCA04` で作成)
   - 却下の根拠をPRコメントに記録する(どの指摘を・なぜ誤検知と判断したか)

4. **修正**: 本修正・妥当nitを**すべて実装してから**、`/verify-all` を通して**1回だけpushする**。
   1件ずつ直して都度pushしない。pushのたびにレビューが1往復消費される。

5. **状態ファイルの記録**(エスカレーション時に人間が読む往復ログ):
   - `.claude/.state/review-loop/pr-<PR番号>/iter-<往復数>.md` に「指摘の要約 / 分類結果 / 対応内容」を書く
   - 同じ内容を要約してPRコメントにも投稿する(`## review-loop 往復<N>` の見出しで。
     PR上に残ることでエスカレーション時に人間が読める)

6. **再判定の確認**: pushでcodex-reviewが自動再実行される。`gh pr checks <PR番号> --watch` で結果を待つ。
   - コード品質・spec適合の両方がLGTMならループ終了。auto-merge予約済みなら、CIの必須チェックが
     すべて成功した時点で自動マージされる
   - どちらかが CHANGES REQUESTED なら次の往復へ(往復数+1)

## エスカレーション(5往復に達した場合)

CIが打ち切りのコメントを投稿し、チェックは赤のまま止まる。停止して人間に報告する。
人間が見るのは「spec/Issue」と「往復ログ(PRコメントのreview-loop履歴)」のみで、
取れる判断は次の3択(コードは読まない):

1. **spec差し戻し**(要求・設計の見直し)
2. **タスク分割してIssue再起票**
3. **PR破棄**

**いずれの場合も、そのPRは閉じて新しいブランチでやり直す。** 同じブランチでPRを作り直しても
往復回数は引き継がれ、打ち切りのままになる。

報告には「何往復目で何が対立しているか」「Codexの主張とClaudeの主張の対立点」を要約して含める。

## Rules

- 誤検知判定を「面倒な指摘の回避」に使わない。根拠を説明できない指摘は本修正として扱う
- 一方で、**前提が事実と異なる指摘まで受け入れて作り直さない**。事実で反証できる場合は
  誤検知として根拠を示して却下する
- **PR本文は最初に確定させ、以後書き換えない**。PR本文とIssue本文はレビューの判定基準であり、
  書き換えると基準そのものが動く
- 矛盾する指摘(過去の往復と逆の指摘等)は、両論を記録した上でどちらに従うかの判断根拠をPRコメントに残す
- 週の誤検知判定が3件を超えたら、レビュープロンプト(codex-review.yml)の見直しをIssue起票する(週次監査でも検知される)

## Report

```
review-loop(PR #NN):
- 往復数: N/5
- 分類: 本修正 X件 / 妥当nit Y件 / 誤検知 Z件(codex-overruled付与: 有/無)
- 判定: LGTM(コード品質・spec適合とも) / 継続 / エスカレーション(打ち切り)
```
